## 1. 项目概述

### 1.1 项目背景

慕声公司在亚马逊平台进行跨境电商业务，涉及美国(US)、加拿大(CA)、英国(UK)、德国(DE)四个站点的销售。根据转口贸易税务申报要求，需要按季度汇总各站点的销售数据、配送费用、广告费用等信息，生成符合税局要求的申报数据。

目前数据处理主要依赖手工Excel操作，效率低且容易出错。本项目旨在开发一套系统化的报税数据处理平台，实现数据导入、清洗、汇总、输出的自动化。

### 1.2 项目目标

- 实现销售数据、配送数据、广告数据、汇率数据的统一管理
- 自动化数据清洗和格式统一
- 支持按季度、站点生成报税汇总数据
- 提供完善的数据追溯和下载功能
- 建立规范的权限管理体系

### 1.3 技术栈

| 类型 | 技术选型 |
|------|----------|
| 后端语言 | Java |
| 数据库 | MySQL |
| 部署方式 | PC端Web应用 |

#### 3.5.3 操作流程

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  上传CSV文件  │────▶│  自动解析表头  │────▶│  识别站点信息  │────▶│  加载映射模板  │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
                                                                       │
                                                                       ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  开始数据导入  │◀────│  保存映射模板  │◀────│  划线配置映射  │◀────│  显示映射画布  │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

**详细步骤**:

1. **上传CSV文件**: 用户选择销售数据CSV文件上传
2. **自动解析表头**: 系统跳过说明行，自动识别表头行并提取所有字段
3. **识别站点信息**: 读取第一条数据的 `marketplace` 字段值，匹配站点配置
4. **加载映射模板**: 
   - 若该站点已有映射模板，自动加载并显示已配置的映射关系
   - 若无模板，显示空白映射画布
5. **显示映射画布**: 
   - 左侧显示CSV文件字段列表
   - 右侧显示销售数据表字段列表（含字段说明）
6. **划线配置映射**: 用户通过拖拽或点击方式建立字段映射关系
7. **保存映射模板**: 保存当前映射配置为该站点的模板
8. **开始数据导入**: 根据映射模板进行数据清洗和导入

#### 3.5.6 数据清洗流程

```
1. 读取CSV文件，跳过说明行，定位表头行
2. 读取第一条数据，获取marketplace值，匹配站点
3. 加载该站点的映射模板
4. 逐行读取数据：
   a. 根据映射配置，将源字段值赋给目标字段
   b. 未映射的字段使用默认值（数值型=0，字符型=空串）
   c. 根据站点配置进行数据格式转换（日期格式、数字格式）
   d. 根据交易类型映射表，设置transaction_category
5. 校验必填字段
6. 检查重复数据（订单号+交易分类）
7. 批量写入数据库
```

#### 3.7.4 数据清洗规则

##### 3.7.4.1 CSV文件结构识别

> **规则**: 需要自动识别表头行和数据起始行

| 行号 | 内容 | 处理方式 |
|------|------|----------|
| 1-7行 | 说明文字（Definitions等） | 跳过 |
| 第8行 | 表头行 | 用于字段映射 |
| 第9行起 | 数据行 | 解析入库 |

**识别逻辑**:
1. 逐行读取CSV
2. 查找包含关键表头字段（如 `date/time` 或 `Datum/Uhrzeit`）的行作为表头
3. 表头下一行开始为数据行

##### 3.7.4.2 站点匹配规则

> **规则**: 根据数据中的 `marketplace` 字段匹配站点配置

```
数据中的 marketplace 值 → 匹配站点配置表中的 Marketplace标识 → 获取站点编码
```

**示例**:
- `amazon.com` → 匹配 → US站点
- `amazon.de` → 匹配 → DE站点
- `Amazon.de`（大小写不同）→ 忽略大小写匹配 → DE站点

**异常处理**: 若 marketplace 值无法匹配任何已配置站点，该条记录标记为错误。

##### 3.7.4.3 数据转换规则

| 转换项 | 规则 | 示例 |
|--------|------|------|
| 日期格式 | 按站点配置的日期格式解析，**保留原始时区** | - |
| 数字格式 | 德国站逗号转点后解析 | 18,48 → 18.48 |
| 货币 | 根据站点自动关联货币 | DE站 → EUR |
| 缺失字段 | **默认值填充0** | Regulatory Fee (UK/DE) → 0 |
| 交易类型 | **保留原始值**，但标记收入/退款分类 | Bestellung → 原值保留，标记为"收入" |

##### 3.7.4.4 交易分类规则

> **规则**: 交易类型保留原始值，但需要区分"收入"和"退款"用于汇总计算

| 原始交易类型 | 收入/退款分类 |
|-------------|--------------|
| Order / Bestellung | 收入 |
| Refund / Erstattung | 退款 |
| 其他类型 | 其他 |

#### 3.7.5 重复数据校验

**校验规则**: 
- 判断条件：**订单号 + 交易状态（支付/退款）**
- 若已存在相同订单号且相同状态的记录，**直接报错**，提示上传人员

**交易状态类型**:
- Order / Bestellung（订单/支付）→ 分类为"收入"
- Refund / Erstattung（退款）→ 分类为"退款"
- 其他类型 → 分类为"其他"

### 3.11 汇总报表模块

#### 3.11.1 功能描述

#### 3.11.2 汇总维度

- **站点维度**: amazon.com / amazon.ca / amazon.co.uk / amazon.de

#### 3.11.3 输出报表格式

**输出文件格式**: CSV / Excel

**输出字段**:

| 字段（英文） | 字段（中文） | 说明 |
|-------------|-------------|------|
| MCID | 卖家记号 | 亚马逊卖家ID |
| Market Place | 亚马逊商城 | 站点名称 |
| Company name | 公司名称 | 固定值 |
| USCC/Taxpayer Identification Number | 统一社会信用代码 | 固定值 |
| Quarter | 季度 | Q1-Q4 |
| Total Revenue | 收入总额 (a) | 销售总额（换算为人民币） |
| Refund Amount | 退款金额 (b) | 退款总额（换算为人民币） |
| Net Income | 收入净额 (c=a-b) | 收入总额 - 退款金额 |
| Platform Fees | 支付给平台的佣金、服务费合计金额 | 亚马逊服务费+广告费 |
| Number of Transactions | 交易（订单）数量（笔） | 订单数量统计 |

#### 3.11.4 汇总计算逻辑

> 参考《报税原始数据处理说明》

```
1. 收入总额（基于配送数据计算）
   收入总额 = Σ(商品价格 + 商品税 + 运费 + 运费税 + 礼品包装价格 + 礼品包装价格税 
              + 商品促销折扣 + 货件促销折扣) × 配送日期汇率

2. 退款金额（基于交易明细表+配送表）
   - 筛选交易类型为 Refund（注意：Refund_Retrocharge 不在计算范畴）
   - 根据订单号在配送表中查找配送日期
   - 以配送日期为准计入对应月份（如7月配送，8月退货，计入7月）
   - 退款金额 = Σ(商品价格 + 商品税 + 运费 + 运费税 + 礼品包装价格 + 礼品包装价格税 
                + 商品促销折扣 + 货件促销折扣) × 配送日期汇率

3. 收入净额
   收入净额 = 收入总额 - 退款金额

4. 亚马逊服务费（基于交易明细表+配送表+汇率表）
   亚马逊服务费 = Σ(|销售费用| + |FBA费用| + |其他交易费|) × 当日汇率
   （具体逻辑待进一步确认）

5. 广告费（按月/季度汇总）
   广告费 = Σ(广告费金额 × 付款时间汇率)

6. 成本计算（扩展）
   成本 = 亚马逊服务费 + 广告费 + 采购金额
   采购金额 = 净收入额 × 96% - 亚马逊服务费 - 广告费

7. 订单数量
   订单数量 = COUNT(DISTINCT 订单号) where 交易分类 = 'income'
```

#### 3.11.5 退款时间归属规则

> **重要**: 退货数据以配送时间为准归属月份

| 场景 | 配送时间 | 退货时间 | 归属月份 |
|------|---------|---------|---------|
| 同月退货 | 7月15日 | 7月25日 | 7月 |
| 跨月退货 | 7月15日 | 8月10日 | **7月** |
| 跨季度退货 | 9月20日 | 10月5日 | **9月（Q3）** |

> **注意**: 拉取退货数据时，时间范围需要比配送表**长两个月**，以确保跨月退货能正确归属。

| 序号 | 问题 | 确认结果 | 确认日期 |

| 1 | 输出格式 | CSV格式，包含10个字段（见3.11.3节） | 2026-01-19 |
| 2 | 汇率换算规则 | 按交易当日汇率计算，节假日顺延 | 2026-01-19 |
| 3 | 配送数据用途 | 记录物流费用（成本），通过订单号与销售数据关联，汇总时参与统计 | 2026-01-19 |
| 4 | 广告发票处理 | 独立模块，手工录入，汇总时按时间节点汇总 | 2026-01-19 |
| 5 | 数据关联关系 | 销售/配送/广告/汇率四个模块独立管理，仅在汇总时参与计算 | 2026-01-19 |
| 6 | 站点合并问题 | 站点只是数据属性，同一模块数据统一存储 | 2026-01-19 |
| 7 | 用户角色 | 管理员（全部权限）、财务人员（除账号管理外）、查看者（按菜单权限） | 2026-01-19 |
| 8 | 重复数据判断 | 按订单号+相同状态（支付/退款）判断，存在则报错提醒 | 2026-01-19 |
| 9 | 缺失字段处理 | 数值型字段默认0，字符型字段默认空串 | 2026-01-19 |
| 10 | 交易类型处理 | 保留原始值，但需区分收入/退款分类 | 2026-01-19 |
| 11 | 时区处理 | 保留原始时区，可根据站点进行转化显示 | 2026-01-19 |
| 12 | 站点匹配方式 | 根据数据中的marketplace字段匹配站点配置 | 2026-01-19 |
| 13 | CSV结构识别 | 需要识别表头行和数据行，不同区域分别处理 | 2026-01-19 |
| 14 | account type字段 | 保留并存储，无时填入默认空串 | 2026-01-19 |
