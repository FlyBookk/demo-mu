## 一、什么是Skill

### 1.1 Skill定义

Skill是项目中配置的自定义命令，用于快速访问项目文档、管理待办事项、切换角色视角等。每个skill都是一个预定义的工作流程，帮助团队成员高效协作。

### 1.2 Skill位置

所有skill配置文件位于：`.claude/skills/` 目录

当前项目配置了5个skill：
- `workflow.md` - 流程规范查询
- `todo.md` - 待办项管理
- `agent.md` - 角色切换
- `review.md` - 评审流程管理
- `doc.md` - 文档搜索

---

## 二、Skill调用机制

### 2.1 调用方式

**重要**：Skill需要**手动调用**，而不是由agent自动执行。

调用格式：
```bash
/skill名称 [参数]
```

### 2.2 调用示例

```bash
/workflow 设计          # 调用workflow skill，参数为"设计"
/todo all              # 调用todo skill，参数为"all"
/agent 前端            # 调用agent skill，参数为"前端"
```

### 2.3 Agent的辅助作用

虽然skill需要手动调用，但Claude agent会：

✅ **主动建议**：根据你的问题，建议使用相关skill
```
你："现在设计阶段要做什么？"
Agent："建议使用 /todo 设计 查看设计阶段待办事项"
```

✅ **解释结果**：执行skill后，解释和分析返回的信息

✅ **提供上下文**：读取相关文档来回答你的深入问题

❌ **不能自动执行**：agent不能代替你调用skill命令

## 三、可用Skill清单

### 3.1 workflow - 流程规范查询

**用途**：查看软件开发协作流程规范

**语法**：
```bash
/workflow              # 查看整体流程概览
/workflow [阶段名称]   # 查看指定阶段详细流程
```

**参数**：
- 无参数：显示五阶段流程概览
- `需求`：显示需求阶段详细流程（需求调研→需求分析→编写PRD→需求评审）
- `设计`：显示设计阶段详细流程（交互设计||前端设计||后端设计→评审）
- `开发`：显示开发阶段详细流程（前端开发||后端开发||测试用例→联调→自测）
- `测试`：显示测试阶段详细流程（冒烟→功能测试→回归测试）
- `验收`：显示验收阶段详细流程（测试验收→产品验收→验收总结）

**使用场景**：
- 新成员了解项目流程
- 进入新阶段前查看流程要求
- 不确定当前阶段应该做什么
- 准备评审会议，查看评审要点

**示例**：
```bash
# 查看整体流程
/workflow

# 查看设计阶段详细流程
/workflow 设计
```

**输出内容**：
- 阶段流程图
- 活动列表（负责人、输入、输出）
- 文档模板结构
- 评审会议要点
- 准入准出标准

---

### 3.2 todo - 待办项管理

**用途**：查看和管理项目各阶段的待办事项

**语法**：
```bash
/todo [阶段名称]                        # 查看待办
/todo [阶段名称] update [任务编号] [状态]  # 更新任务
```

**参数**：
- `阶段名称`：all | 需求 | 设计 | 开发 | 测试 | 验收
- `任务编号`：如 1.1, 2.3, 5.6
- `状态`：待处理 | 进行中 | 已完成

**文档映射**：
| 阶段 | 文档路径 |
|------|---------|
| all | `项目文档/05_项目管理/项目总待办项.md` |
| 需求 | `项目文档/05_项目管理/需求阶段待办项.md` |
| 设计 | `项目文档/05_项目管理/设计阶段待办项.md` |
| 开发 | `项目文档/05_项目管理/开发阶段待办项.md` |
| 测试 | `项目文档/05_项目管理/测试阶段待办项.md` |
| 验收 | `项目文档/05_项目管理/验收阶段待办项.md` |

**使用场景**：
- 每日站会前查看今日待办
- 完成任务后更新状态
- 查看项目整体进度
- 识别阻塞问题

**示例**：
```bash
# 查看项目整体进度
/todo all

# 查看设计阶段待办
/todo 设计

# 更新任务状态
/todo 设计 update 2.6 已完成
```

**输出内容**：
- 进度统计（完成率）
- 已完成任务列表
- 进行中任务列表
- 待处理任务列表
- 阻塞问题（P0问题）
- 下一步计划

### 3.3 agent - 角色切换

**用途**：切换到特定角色视角，聚焦该角色相关的工作内容

**语法**：
```bash
/agent [角色名称]        # 切换角色
/agent [角色名称] tasks  # 查看角色任务清单
/agent reset            # 退出角色模式
```

**参数**：
- `角色名称`：产品 | 设计 | 前端 | 后端 | 测试
- `tasks`：查看该角色的全阶段任务清单
- `reset`：退出角色模式，恢复全局视角

**角色映射**：
| 角色 | Agent文件 | 主要职责 |
|------|----------|---------|
| 产品 | `agent-product.md` | 需求调研、需求分析、产品规划、验收把控 |
| 设计 | `agent-design.md` | 交互方案设计、原型制作、视觉规范 |
| 前端 | `agent-frontend.md` | 前端架构设计、页面开发、接口对接 |
| 后端 | `agent-backend.md` | 后端架构设计、接口开发、数据库设计 |
| 测试 | `agent-test.md` | 测试策略制定、用例编写、缺陷跟踪 |

**使用场景**：
- 开始工作前切换到自己的角色
- 查看自己负责的任务
- 了解自己在各阶段的职责
- 查看需要协作的事项

**示例**：
```bash
# 切换到前端角色
/agent 前端

# 查看测试角色的全部任务
/agent 测试 tasks

# 退出角色模式
/agent reset
```

**输出内容（角色工作台）**：
- 当前项目状态
- 我的待办任务（按优先级）
- 今日焦点（智能推荐）
- 我的文档（需要输出/参考/待评审）
- 需要协作（与其他角色）
- 风险提示
- 快捷命令

**特殊功能**：
切换角色后，其他命令会自动过滤：
- `/todo` 只显示该角色相关任务
- `/workflow` 高亮该角色的活动
- `/review` 标注该角色的评审职责

### 3.4 review - 评审流程管理

**用途**：启动和管理项目的各类标准化评审流程

**语法**：
```bash
/review [类型]         # 启动评审
/review [类型] record  # 查看评审记录
```

**参数**：
- `类型`：需求 | 交互 | 技术 | 用例 | 验收
- `record`：查看已有的评审记录

**评审类型映射**：
| 评审类型 | 阶段 | 参与角色 | 评审材料 | 输出文档 |
|---------|------|---------|---------|---------|
| 需求评审 | 需求 | 全员 | PRD文档 | `需求评审记录.md` |
| 交互评审 | 设计 | 全员 | 交互设计文档 | `设计评审记录.md` |
| 技术评审 | 设计 | 前端+后端+测试 | 技术设计文档 | `设计评审记录.md` |
| 用例评审 | 开发 | 测试+研发 | 测试用例文档 | `用例评审记录.md` |
| 验收评审 | 验收 | 全员 | 测试验收文档 | `验收总结报告.md` |

**使用场景**：
- 准备评审会议，查看评审标准
- 会议中记录评审问题
- 会后查看评审记录和待解决问题
- 跟踪评审问题解决进度

**示例**：
```bash
# 启动技术设计评审
/review 技术

# 查看技术评审记录
/review 技术 record
```

**输出内容（启动评审）**：
- 前置检查（材料是否就绪）
- 参与角色（必须/可选）
- 评审要点清单
- 评审流程
- 通过标准
- 评审记录模板

**输出内容（查看记录）**：
- 评审时间和结论
- 问题统计（按优先级）
- 待解决问题列表
- 已解决问题列表
- 下一步计划

### 3.5 doc - 文档搜索

**用途**：快速查找和查看项目中的各类文档

**语法**：
```bash
/doc [类型]              # 查看该类型所有文档
/doc [类型] [关键词]      # 在该类型中搜索关键词
/doc search [关键词]      # 全局搜索
/doc list [类型]         # 列出文档树形结构
```

**参数**：
- `类型`：需求 | 设计 | 测试 | 评审 | 管理 | 部署 | 业务 | 流程 | 角色
- `关键词`：搜索关键词

**文档类型映射**：
| 类型 | 目录路径 | 包含文档 |
|------|---------|---------|
| 需求 | `项目文档/01_需求文档/` | PRD、需求评审记录 |
| 设计 | `项目文档/02_设计文档/` | 交互设计、前后端技术设计 |
| 测试 | `项目文档/03_测试文档/` | 测试用例、测试报告、测试验收 |
| 评审 | `项目文档/04_评审记录/` | 各类评审记录 |
| 管理 | `项目文档/05_项目管理/` | 各阶段待办项 |
| 部署 | `项目文档/06_部署文档/` | 部署指南、环境配置 |
| 业务 | 根目录 | 业务流程、数据处理说明 |

**使用场景**：
- 寻找特定文档
- 搜索某个功能点的设计方案
- 查看文档完整性
- 了解文档依赖关系

**示例**：
```bash
# 查看所有设计文档
/doc 设计

# 在设计文档中搜索"字段映射"
/doc 设计 字段映射

# 全局搜索关键词
/doc search 字段映射

# 列出评审记录文档树
/doc list 评审
```

**输出内容**：
- 文档列表（路径、状态、更新时间）
- 文档结构（章节目录）
- 相关文档（依赖、被引用）
- 搜索匹配内容预览
- 文档完整性检查

## 六、常见问题

### Q1: Skill命令无效怎么办？

**问题**：输入 `/workflow` 后提示 "skill not found"

**解决方案**：
1. 检查skill文件是否存在：`ls .claude/skills/`
2. 检查skill文件格式是否正确（需要YAML头部）
3. 重启Claude Code会话
4. 确认Claude Code版本支持自定义skill

---

### Q2: Skill会自动执行吗？

**回答**：不会。Skill需要你主动调用，格式为 `/skill名称 [参数]`

Claude agent会根据你的问题建议使用某个skill，但不会自动执行。

---

### Q3: 切换角色后如何退出？

**回答**：使用 `/agent reset` 命令退出角色模式，恢复全局视角。

---

### Q4: 如何查看某个skill的详细说明？

**回答**：
1. 直接查看skill文件：`cat .claude/skills/[skill名称].md`
2. 调用skill时不带参数，通常会显示帮助信息
3. 参考本文档第三章的详细说明

---

### Q5: 待办项更新后文档会自动保存吗？

**回答**：是的。使用 `/todo [阶段] update [任务] [状态]` 命令后，对应的待办项文档会自动更新并保存。

---

### Q6: 可以自定义新的skill吗？

**回答**：可以。在 `.claude/skills/` 目录下创建新的 `.md` 文件，按照以下格式：

```markdown
---
name: 你的skill名称
description: skill描述
---

# Skill说明

[详细说明内容]
```

---

### Q7: Skill支持的参数有哪些限制？

**回答**：每个skill支持的参数在skill定义文件中有说明。参数通常是：
- 阶段名称：需求、设计、开发、测试、验收
- 角色名称：产品、设计、前端、后端、测试
- 文档类型：需求、设计、测试、评审、管理等

参数是大小写敏感的，建议使用中文参数。

---

### Q8: 如何知道当前处于哪个角色模式？

**回答**：
1. 切换角色后，agent会在响应中提示 "已切换到 [角色] 视角"
2. 后续的命令输出会自动过滤为该角色相关内容
3. 可以使用 `/agent reset` 退出角色模式

---

### Q9: 多个人同时更新待办项会冲突吗？

**回答**：会。待办项文档是文件形式存储，多人同时修改可能产生冲突。建议：
1. 使用Git管理文档版本
2. 更新前先拉取最新版本
3. 团队约定谁负责更新哪些阶段的待办项

---

### Q10: Skill能在其他项目中复用吗？

**回答**：可以。将 `.claude/skills/` 目录复制到其他项目，并根据项目实际情况调整：
1. 文档路径映射
2. 角色定义
3. 阶段划分
4. 评审类型
