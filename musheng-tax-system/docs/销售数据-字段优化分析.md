### 1.2 站点差异总结

| 差异点 | 具体说明 |
|--------|----------|
| **语言差异** | DE站为德语表头，其他站为英语 |
| **账户类型** | 仅US站有 `account type` 字段 |
| **监管费** | 仅CA/US站有 `Regulatory Fee` 及其税字段 |
| **运费字段名** | UK站用 `postage credits`，其他站用 `shipping credits` |
| **礼品包装税** | CA/UK用 `giftwrap credits tax`（无空格），US用 `giftwrap credits tax` |

### 4.3 优化后表结构

```sql
CREATE TABLE t_sales_data (
    -- 系统字段
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    import_batch_id BIGINT COMMENT '导入批次ID',
    source_type VARCHAR(20) NOT NULL COMMENT '数据源类型(ORIGINAL/ERP)',
    
    -- 业务标识字段
    store_name VARCHAR(100) COMMENT '店铺名称',
    transaction_date DATETIME NOT NULL COMMENT '交易/结算时间',
    settlement_id VARCHAR(50) NOT NULL COMMENT '亚马逊结算批次号',
    transaction_type VARCHAR(50) NOT NULL COMMENT '交易类型(Order/Refund/Shipment等)',
    transaction_category VARCHAR(20) COMMENT '交易分类(income/refund/fee/adjustment/other)',
    order_id VARCHAR(50) NOT NULL COMMENT '亚马逊订单编号',
    sku VARCHAR(100) COMMENT '商品SKU',
    description VARCHAR(500) COMMENT '商品描述',
    quantity INT DEFAULT 0 COMMENT '商品数量',
    
    -- 站点与货币字段
    site_code VARCHAR(10) COMMENT '站点代码(US/UK/DE等)',
    marketplace VARCHAR(50) COMMENT '站点域名(amazon.de等)',
    currency_code VARCHAR(10) COMMENT '货币代码(USD/EUR/GBP等)',
    fulfillment VARCHAR(50) COMMENT '配送方式(FBA/FBM)',
    
    -- 费用字段（全部保留）
    product_sales DECIMAL(15,2) DEFAULT 0 COMMENT '产品销售额',
    product_sales_tax DECIMAL(15,2) DEFAULT 0 COMMENT '产品税',
    shipping_credits DECIMAL(15,2) DEFAULT 0 COMMENT '运费收入',
    shipping_credits_tax DECIMAL(15,2) DEFAULT 0 COMMENT '运费税',
    gift_wrap_credits DECIMAL(15,2) DEFAULT 0 COMMENT '礼品包装费',
    gift_wrap_credits_tax DECIMAL(15,2) DEFAULT 0 COMMENT '礼品包装税',
    regulatory_fee DECIMAL(15,2) DEFAULT 0 COMMENT '监管费(仅CA/US)',
    regulatory_fee_tax DECIMAL(15,2) DEFAULT 0 COMMENT '监管费税(仅CA/US)',
    promotional_rebates DECIMAL(15,2) DEFAULT 0 COMMENT '促销折扣',
    promotional_rebates_tax DECIMAL(15,2) DEFAULT 0 COMMENT '促销折扣税',
    marketplace_withheld_tax DECIMAL(15,2) DEFAULT 0 COMMENT '平台代扣税',
    selling_fees DECIMAL(15,2) DEFAULT 0 COMMENT '销售佣金',
    fba_fees DECIMAL(15,2) DEFAULT 0 COMMENT 'FBA配送费',
    other_transaction_fees DECIMAL(15,2) DEFAULT 0 COMMENT '其他交易费',
    other DECIMAL(15,2) DEFAULT 0 COMMENT '其他金额',
    total DECIMAL(15,2) DEFAULT 0 COMMENT '合计',
    
    -- 汇率字段
    exchange_rate DECIMAL(10,6) COMMENT '当日汇率',
```

## 6. 去重逻辑统一

### 6.1 统一去重键

**唯一键组成**：`settlement_id + order_id + transaction_type + sku`

| 字段 | 作用 | 说明 |
|------|------|------|
| **settlement_id** | 结算批次 | 亚马逊结算周期标识 |
| **order_id** | 订单号 | 可为空（费用类记录） |
| **transaction_type** | 交易类型 | Order/Refund/仓储费等 |
| **sku** | 商品SKU | 区分同订单不同商品 |

**设计理由**：
- 该组合可处理**无订单号的费用类记录**（如仓储费、服务费），通过 `sku` 区分
- 同一订单的多个SKU可以正确区分
- **不包含 transaction_date**：原始数据和ERP数据的时间不一致，无法作为约束条件

### 6.2 关键对应关系

| 字段 | 原始数据来源 | ERP数据来源 | 数据库字段 |
|------|-------------|-------------|-----------|
| 结算ID | `settlement id` 列 | `Settlement ID` 列 | settlement_id |
| 订单号 | `order id` 列 | `订单号` 列 | order_id |
| 交易类型 | `type` 列 | `来源` 列 | transaction_type |
| SKU | `sku` 列 | `MSKU` 列 | sku |

### 6.3 数据库索引

```sql
INDEX idx_sales_dedup (settlement_id, order_id, transaction_type, sku)
```

> **注意**：ERP数据使用 `Settlement ID` 列（亚马逊原始结算ID），而非 `结算编号` 列（ERP内部编号）

## 7. t_transaction_type_mapping 表分析

### 7.1 当前用途

该表原设计用于配置化的交易类型映射，但实际上：
- ERP交易类型映射已硬编码在 `ErpSettlementParser.ERP_TYPE_TO_FIELD` 中
- 原始数据的 type 字段直接存储，无需映射

### 7.2 建议

**建议删除此表**，原因：
1. ERP交易类型到金额字段的映射是固定的业务逻辑，适合代码实现
2. 通过代码硬编码更易于维护和调试
3. 减少不必要的数据库查询
