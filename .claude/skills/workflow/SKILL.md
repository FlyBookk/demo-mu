# 工作流程查询 Skill

此 skill 用于快速查看项目的标准化开发流程。

## 使用方法

```bash
/workflow [阶段名称]
```

## 参数说明

- `阶段名称`（可选）：需求 | 设计 | 开发 | 测试 | 验收 | all
  - 如果不提供参数，显示整体流程概览
  - 如果提供具体阶段，显示该阶段的详细流程

## 功能说明

当用户调用此 skill 时，你应该：

1. **读取流程规范文档**
   - 主文档：`.agent/workflows/flow.md`
   - 这个文档包含完整的5阶段协作流程

2. **根据参数返回对应内容**

   - `all` 或无参数：显示整体流程概览
     - 五个阶段的流程图
     - 各阶段的主要角色和产出物

   - `需求`：显示需求阶段详细流程
     - 流程图
     - 活动说明（需求调研、需求分析、编写PRD、需求评审）
     - PRD文档模板结构
     - 需求评审会议要点

   - `设计`：显示设计阶段详细流程
     - 流程图（交互设计、前端技术设计、后端技术设计并行）
     - 活动说明
     - 各类设计文档模板
     - 评审会议要点

   - `开发`：显示开发阶段详细流程
     - 流程图（前端开发、后端开发、测试用例编写并行）
     - 活动说明
     - 测试用例文档模板
     - 联调和提测流程

   - `测试`：显示测试阶段详细流程
     - 流程图
     - 测试活动说明（冒烟、功能、回归）
     - 缺陷管理规范

   - `验收`：显示验收阶段详细流程
     - 流程图
     - 验收活动说明
     - 验收标准

3. **额外提供相关信息**
   - 该阶段的角色职责
   - 准入准出标准
   - 相关文档路径
   - 评审规范

## 输出格式

使用清晰的 markdown 格式输出，包含：
- 流程图（使用 ASCII 或文本描述）
- 活动列表
- 角色分工
- 交付物清单
- 相关文档链接

## 示例

用户输入：`/workflow 设计`

应该输出设计阶段的：
- 并行流程（交互设计 || 前端设计 || 后端设计）
- 两次评审（交互设计评审 -> 技术设计评审）
- 各角色职责
- 设计文档模板结构
- 评审标准
