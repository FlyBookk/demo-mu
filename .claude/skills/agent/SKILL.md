# Agent 角色切换 Skill

此 skill 用于切换到特定的 agent 角色视角，聚焦该角色相关的工作内容。

## 使用方法

```bash
/agent [角色名称]
/agent [角色名称] tasks
/agent reset
```

## 参数说明

- `角色名称`：产品 | 设计 | 前端 | 后端 | 测试
- `tasks`（可选）：查看该角色的具体任务清单
- `reset`：退出角色模式，恢复默认视角

## 角色映射

| 角色名称 | Agent文件 | 主要职责 | 关注文档 |
|---------|----------|---------|---------|
| 产品 | `.claude/agents/agent-product.md` | 需求调研、需求分析、产品规划、验收把控 | PRD、评审记录、验收文档 |
| 设计 | `.claude/agents/agent-design.md` | 交互方案设计、原型制作、视觉规范 | 交互设计文档、原型图 |
| 前端 | `.claude/agents/agent-frontend.md` | 前端架构设计、页面开发、接口对接 | 前端技术设计、代码 |
| 后端 | `.claude/agents/agent-backend.md` | 后端架构设计、接口开发、数据库设计 | 后端技术设计、接口文档 |
| 测试 | `.claude/agents/agent-test.md` | 测试策略制定、用例编写、缺陷跟踪 | 测试用例、测试报告 |

## 功能说明

### 1. 切换角色视角（默认行为）

当用户调用 `/agent [角色]` 时：

#### 步骤1：加载角色定义
1. 读取对应的 agent 定义文件
2. 解析角色的：
   - 职责范围
   - 工作流程
   - 输出标准
   - 协作要求

#### 步骤2：展示角色仪表盘
根据角色展示定制化的工作视图：

```markdown
## 👤 [角色名称] 工作台

### 📊 当前状态
- 当前项目阶段: [阶段]
- 我的任务状态: X个待办 / Y个进行中 / Z个已完成
- 我负责的阶段: [阶段列表]

### 📋 我的待办任务
[从各阶段待办项中筛选该角色相关的任务]

1. ⏳ [任务1] - [所属阶段]
2. ⏳ [任务2] - [所属阶段]
3. 🔲 [任务3] - [所属阶段]

### 🎯 今日焦点
[根据项目当前阶段，建议该角色应该关注的重点]

### 📂 我的文档
[该角色需要输出或参考的文档列表]
- 需要输出: [文档列表]
- 需要参考: [文档列表]
- 待评审: [文档列表]

### 🤝 需要协作
[该角色当前需要与其他角色协作的事项]

### ⚠️ 风险提示
[该角色需要注意的风险和阻塞项]

### 📚 角色指南
[快速访问该角色的工作指南和规范]
```

#### 步骤3：过滤显示相关内容
在角色模式下，后续的工具调用会自动过滤：
- `/todo` 命令只显示该角色相关的任务
- `/workflow` 命令高亮该角色的活动
- `/review` 命令标注该角色的评审职责

### 2. 查看角色任务（tasks 模式）

当用户调用 `/agent [角色] tasks` 时：

详细列出该角色在各阶段的具体任务：

```markdown
## [角色名称] - 全阶段任务清单

### 需求阶段
**参与度**: ⭐⭐⭐⭐⭐ 主导 / ⭐⭐⭐ 参与 / ⭐ 知晓
- [ ] [任务1]
- [ ] [任务2]

### 设计阶段
**参与度**: ⭐⭐⭐⭐⭐
- [ ] [任务1]
- [ ] [任务2]

[...]
```

### 3. 退出角色模式（reset）

当用户调用 `/agent reset` 时：
- 清除角色过滤
- 恢复全局视角
- 显示退出提示

## 各角色的工作视图定制

### 产品角色视图
**关注重点**：
- 需求阶段的所有活动
- 各阶段的评审（需求评审、交互评审、验收评审）
- 功能完整性和用户体验

**工作文档**：
- 输出：PRD、需求评审记录、验收问题清单、验收总结报告
- 参考：交互设计文档、测试报告

**协作事项**：
- 需与交互设计确认交互方案
- 需与测试确认验收标准
- 需在各阶段提供业务支持

---

### 设计角色视图
**关注重点**：
- 设计阶段的交互设计活动
- 交互设计评审
- 用户体验和视觉一致性

**工作文档**：
- 输出：交互设计文档、原型图、组件规范
- 参考：PRD、前端技术设计

**协作事项**：
- 需与产品确认需求理解
- 需与前端确认技术可行性
- 需参与验收评审

---

### 前端角色视图
**关注重点**：
- 设计阶段的前端技术设计
- 开发阶段的前端开发
- 技术设计评审、用例评审
- 与后端的接口联调

**工作文档**：
- 输出：前端技术设计文档、前端代码、联调报告、自测报告
- 参考：PRD、交互设计文档、后端接口文档

**协作事项**：
- 需与交互设计确认实现方案
- 需与后端对齐接口协议
- 需与测试确认用例可执行性

---

### 后端角色视图
**关注重点**：
- 设计阶段的后端技术设计
- 开发阶段的后端开发
- 技术设计评审、用例评审
- 数据库设计和性能优化

**工作文档**：
- 输出：后端技术设计文档、后端代码、接口文档、DDL脚本、联调报告、自测报告
- 参考：PRD、数据字典

**协作事项**：
- 需与前端对齐接口协议
- 需与测试确认用例可执行性
- 需提供数据库设计评审

---

### 测试角色视图
**关注重点**：
- 所有阶段的可测试性评审
- 开发阶段的测试用例编写
- 测试阶段的测试执行
- 验收阶段的测试验收

**工作文档**：
- 输出：测试用例文档、缺陷报告、测试报告、测试验收文档
- 参考：PRD、交互设计文档、技术设计文档

**协作事项**：
- 需在各阶段评审可测试性
- 需与研发确认用例合理性
- 需与产品确认验收标准

---

## 智能提示

1. **阶段提醒**
   - 根据项目当前阶段，提醒该角色应该做什么
   - 如果不是该角色的主导阶段，说明参与方式

2. **依赖提醒**
   - 如果该角色的任务依赖其他角色，显示依赖状态
   - 如果有其他角色在等待该角色，给出提醒

3. **文档状态**
   - 该角色负责的文档是否已完成
   - 该角色需要参考的文档是否已就绪

4. **评审提醒**
   - 即将进行的评审中，该角色是否需要参与
   - 该角色组织的评审是否已安排
