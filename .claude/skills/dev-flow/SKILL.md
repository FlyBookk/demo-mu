# 功能开发流程 Skill

此 skill 用于执行标准化的前端功能开发流程。

## 使用方法

```bash
/dev-flow [功能名称]
```

## 参数说明

- `功能名称`（必填）：要开发的功能名称，如"字段映射画布"、"文件上传组件"等

## 功能说明

自动化执行前端功能开发的完整流程，包括：
1. 角色切换
2. 需求确认
3. 文档搜索
4. 技术方案设计
5. 代码开发
6. 自测验证
7. 待办更新

---

## 执行流程

当用户调用 `/dev-flow [功能名称]` 时，按照以下步骤执行：

### 步骤1：切换到前端角色
```
调用: /agent 前端
```
- 切换到前端研发视角
- 查看当前项目状态
- 确认当前阶段和待办任务

### 步骤2：确认开发任务
- 从待办列表中确认该功能是否存在
- 如果存在，标记为 `in_progress`
- 如果不存在，询问用户是否需要创建待办任务

### 步骤3：搜索相关文档
```
调用: /doc [功能名称]
```
- 搜索需求文档中的相关内容
- 搜索设计文档中的相关内容
- 搜索技术设计中的相关定义
- 列出找到的关键信息

### 步骤4：分析技术方案
基于搜索到的文档，分析：
- **组件位置**：该功能应该放在哪个目录下
- **技术选型**：需要使用的技术栈和第三方库
- **接口依赖**：需要对接的后端接口
- **状态管理**：是否需要Store管理状态
- **公共组件**：是否可以复用现有组件
- **类型定义**：需要定义的TypeScript类型

### 步骤5：生成开发计划
输出结构化的开发计划：

```markdown
## 📋 [功能名称] 开发计划

### 基本信息
- 功能名称: [名称]
- 所属模块: [模块]
- 开发阶段: [阶段]
- 预计复杂度: 简单/中等/复杂

### 需要创建的文件
1. `src/components/.../index.vue` - 主组件
2. `src/components/.../types.ts` - 类型定义
3. `src/api/xxx.ts` - API接口（如需要）
4. `src/composables/useXxx.ts` - 组合式函数（如需要）

### 技术要点
- [ ] 使用 Vue 3 Composition API
- [ ] TypeScript 类型定义完整
- [ ] Props 定义和默认值
- [ ] Emits 事件定义
- [ ] 样式使用 SCSS scoped

### 接口依赖
- GET /api/v1/xxx - 获取数据
- POST /api/v1/xxx - 提交数据

### 开发步骤
1. 创建组件文件结构
2. 定义 TypeScript 类型
3. 实现组件逻辑
4. 编写样式
5. 本地测试验证

是否开始开发？（是/否/修改计划）
```

### 步骤6：执行开发
用户确认后，开始执行开发：

#### 6.1 创建文件结构
根据开发计划创建必要的文件和目录

#### 6.2 编写类型定义
- 创建 TypeScript 类型文件
- 定义 Props、Emits、数据结构类型

#### 6.3 实现组件代码
- 使用项目代码模板
- 遵循项目编码规范
- 添加必要的注释

#### 6.4 编写样式
- 使用 SCSS scoped
- 遵循项目样式规范

#### 6.5 API接口封装
如果需要调用后端接口：
- 在 `src/api/` 目录下创建或更新API文件
- 使用统一的 request 封装
- 添加完整的类型定义

### 步骤7：自测验证
开发完成后，执行自测：

```markdown
## 自测清单

- [ ] 代码可以正常编译
- [ ] 没有 TypeScript 类型错误
- [ ] 没有 ESLint 警告
- [ ] 组件可以正常渲染
- [ ] Props 传递正常
- [ ] Events 触发正常
- [ ] 样式显示正确
- [ ] 响应式正常
- [ ] 边界情况处理
- [ ] 错误处理完善
```

执行命令：
```bash
npm run dev
```

询问用户：功能是否正常？是否需要调试？

### 步骤8：生成自测报告（如果需要）
如果已进入开发阶段，生成自测报告文档

### 步骤9：更新待办状态
```
使用 TodoWrite 工具标记任务完成
```

### 步骤10：输出总结
```markdown
## ✅ [功能名称] 开发完成

### 已创建文件
- [文件列表]

### 已实现功能
- [功能点列表]

### 测试结果
- ✅ 编译通过
- ✅ 功能正常
- ✅ 样式正确

### 下一步
- [ ] 联调对接（如需要）
- [ ] 提交代码评审
- [ ] 集成到主流程

---

💡 提示：
- 可以运行 `npm run lint` 检查代码规范
- 可以调用 `/review 代码评审` 进行代码评审
```

## 错误处理

### 文档未找到
如果搜索不到相关文档，提示用户：
- 该功能可能是新增需求
- 建议先创建需求文档或技术设计文档
- 询问用户是否继续开发

### 接口未定义
如果发现需要的后端接口未定义：
- 列出缺失的接口
- 建议与后端协调
- 可以先使用 Mock 数据开发

### 依赖缺失
如果缺少必要的依赖或组件：
- 列出缺失项
- 提供安装建议
- 询问是否先解决依赖

## 注意事项

1. **遵循项目规范**：严格遵循项目的编码规范、目录结构、命名约定
2. **类型安全**：所有代码必须有完整的 TypeScript 类型定义
3. **代码复用**：优先复用现有组件和工具函数
4. **性能优化**：大型组件考虑懒加载、虚拟滚动等优化方案
5. **错误处理**：完善的错误处理和边界情况处理
6. **文档先行**：如果文档缺失，建议先补充文档再开发
