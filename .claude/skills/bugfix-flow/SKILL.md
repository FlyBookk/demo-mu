# Bug修复流程 Skill

此 skill 用于执行标准化的Bug修复流程。

## 使用方法

```bash
/bugfix [Bug描述或ID]
```

## 参数说明

- `Bug描述或ID`（必填）：Bug的简要描述或缺陷ID，如"登录失败"、"表格数据不刷新"等

## 功能说明

自动化执行Bug修复的完整流程，包括：
1. Bug信息收集
2. 问题定位
3. 根因分析
4. 修复方案设计
5. 代码修复
6. 回归测试
7. 文档更新

---

## 执行流程

当用户调用 `/bugfix [Bug描述]` 时，按照以下步骤执行：

### 步骤1：切换到前端角色
```
调用: /agent 前端
```

### 步骤2：收集Bug信息
询问用户提供以下信息（如果未提供）：

```markdown
## 🐛 Bug信息收集

### 基本信息
- **Bug描述**: [简要描述]
- **优先级**: P0/P1/P2/P3
- **影响模块**: [模块名称]
- **发现阶段**: 开发/测试/验收/生产
- **报告人**: [姓名]

### 重现步骤
1. [步骤1]
2. [步骤2]
3. [步骤3]

### 预期结果
[应该出现什么]

### 实际结果
[实际出现了什么]

### 错误信息
```
[控制台错误/报错信息]
```

### 环境信息
- 浏览器: Chrome/Firefox/Safari [版本]
- 操作系统: Windows/Mac/Linux
- 前端版本: [版本号]

### 截图/录屏
[如有]
```

### 步骤3：搜索相关代码
```
调用: /doc [Bug相关模块]
```

基于Bug描述，搜索相关的：
- 组件代码
- API接口
- 状态管理
- 路由配置
- 工具函数

### 步骤4：问题定位
根据Bug信息和代码搜索结果，进行问题定位：

```markdown
## 🔍 问题定位

### 可能原因分析
1. **原因1**: [分析]
   - 相关代码: `src/xxx/yyy.vue:123`
   - 可能性: 高/中/低

2. **原因2**: [分析]
   - 相关代码: `src/xxx/zzz.ts:45`
   - 可能性: 高/中/低

### 需要检查的文件
- [ ] `src/components/xxx/index.vue`
- [ ] `src/api/xxx.ts`
- [ ] `src/stores/modules/xxx.ts`

### 需要验证的假设
1. [假设1]
2. [假设2]
```

询问用户：是否需要查看某个具体文件？

### 步骤5：根因分析
读取相关代码文件，进行根因分析：

```markdown
## 🎯 根因分析

### 问题根源
[详细说明问题的根本原因]

### 代码位置
- 文件: `src/xxx/yyy.vue`
- 行号: `123-145`
- 问题代码:
```typescript
// 当前代码
const data = response.data.list // Bug: 当 data 为 null 时会报错
```

### 影响范围
- ✅ 仅影响 [模块A]
- ⚠️ 可能影响 [模块B]
- ❌ 不影响其他模块

### 严重程度评估
- P0: 系统崩溃/核心功能不可用 → 立即修复
- P1: 主要功能异常 → 当天修复
- P2: 次要功能异常 → 本周修复
- P3: 体验优化 → 排期修复
```

### 步骤6：设计修复方案
基于根因分析，设计修复方案：

```markdown
## 🛠️ 修复方案

### 方案一（推荐）
**描述**: [方案说明]

**修改内容**:
- 文件: `src/xxx/yyy.vue:123`
- 修改:
```typescript
// 修复后代码
const data = response.data?.list || [] // 添加可选链和默认值
```

**优点**:
- [优点1]
- [优点2]

**风险**:
- [风险1]

### 方案二（备选）
**描述**: [方案说明]
**修改内容**: [...]
**优点**: [...]
**风险**: [...]

### 推荐方案: 方案一

是否采用推荐方案？（是/否/修改方案）
```

### 步骤7：执行修复
用户确认方案后，执行代码修复：

#### 7.1 读取相关文件
使用 Read 工具读取需要修改的文件

#### 7.2 修改代码
使用 Edit 工具修改代码：
- 精确定位问题代码
- 实施修复方案
- 添加必要的注释
- 完善错误处理

#### 7.3 相关文件更新
如果需要，更新相关文件：
- 类型定义
- 单元测试
- 文档注释

### 步骤8：自测验证
修复完成后，执行自测：

```markdown
## ✅ 自测清单

### 编译检查
- [ ] 代码可以正常编译
- [ ] 没有 TypeScript 类型错误
- [ ] 没有 ESLint 警告

### 功能验证
- [ ] Bug重现步骤不再出现问题
- [ ] 修复后功能正常
- [ ] 边界情况正常

### 回归测试
- [ ] 相关功能未受影响
- [ ] 其他模块未受影响

### 性能检查
- [ ] 无性能劣化
```

执行命令：
```bash
npm run dev
```

引导用户：
1. 按照Bug重现步骤操作
2. 验证Bug是否已修复
3. 测试相关功能是否正常
4. 检查是否引入新问题

询问用户：Bug是否已修复？是否需要调整？

### 步骤9：生成修复报告
```markdown
## 📋 Bug修复报告

### Bug信息
- **Bug ID**: [ID]
- **Bug描述**: [描述]
- **优先级**: P0/P1/P2
- **影响模块**: [模块]

### 根本原因
[问题的根本原因说明]

- ✅ Bug已修复

- ✅ 无新增问题

### 代码变更
```diff

### 步骤10：更新待办和文档
- 使用 TodoWrite 标记Bug修复完成
- 如果是P0/P1级别Bug，记录到缺陷跟踪文档
- 更新测试用例（如需要）

### 步骤11：提交评审
提示用户：
```markdown
Bug修复完成，建议：

1. **提交代码**
```bash
git add .
git commit -m "fix: [Bug描述]

- 修复了 [具体问题]
- 影响范围: [模块]
- 测试: [测试说明]
```

2. **代码评审**
```
/review 代码评审
```

3. **回归测试**
提交测试团队进行回归测试
```

## 错误处理

### Bug信息不完整
如果用户提供的Bug信息不足以定位问题：
- 列出缺失的关键信息
- 引导用户补充信息
- 必要时建议与测试/用户沟通

### 无法定位问题
如果搜索代码后仍无法定位问题：
- 建议用户提供更多上下文
- 推荐使用浏览器调试工具
- 建议添加日志进行排查

### 修复方案不确定
如果问题复杂，修复方案不明确：
- 列出多个可能方案
- 说明各方案的优缺点
- 建议与团队讨论
- 推荐先在本地验证

## 示例

### 示例1：修复表格刷新问题
```
用户: /bugfix 表格数据不刷新

流程：
1. 收集Bug信息
   - 描述: 删除数据后表格不刷新
   - 模块: 销售数据列表
   - 重现: 点击删除 → 确认删除 → 表格数据未更新

2. 搜索相关代码
   /doc 销售数据列表

3. 定位问题
   - 文件: src/views/sales/list/index.vue
   - 问题: 删除成功后未调用刷新方法

4. 根因分析
   - handleDelete 方法缺少 fetchData() 调用

5. 修复方案
   - 在删除成功后添加 fetchData()

6. 执行修复
   - 修改代码添加刷新调用

7. 自测验证
   - 删除数据 → 表格自动刷新 ✅

8. 生成报告并提交评审
```

### 示例2：修复登录失败问题
```
用户: /bugfix 登录失败提示401错误

流程：
1. 收集信息
   - 错误: 401 Unauthorized
   - 控制台: Token过期

2. 搜索代码
   /doc 登录接口

3. 定位问题
   - src/utils/request.ts 响应拦截器

4. 根因分析
   - Token过期未自动刷新

5. 修复方案
   - 添加Token刷新逻辑

6. 执行修复

7. 测试验证

8. 提交评审
```

---

## 注意事项

1. **优先级判断**：P0/P1问题立即修复，P2/P3合理排期
2. **影响范围评估**：修复前评估影响范围，避免引入新问题
3. **回归测试**：修复后必须执行回归测试
4. **根因分析**：治标更要治本，找到问题根源
5. **举一反三**：检查是否有类似问题需要一并修复
6. **文档更新**：重要Bug修复需更新文档和测试用例
