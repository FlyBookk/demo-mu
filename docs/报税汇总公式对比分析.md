## 一、收入总额

### 数据源
配送货件表（ShippingData）

### 筛选条件
发货日期（shipDate）在目标季度范围内

### 计算公式

```
收入总额 = Σ（每笔配送的收入小计 × 发货日期当天汇率）

收入小计 = 商品价格 + 商品税 + 运费 + 运费税 + 礼品包装价格 + 礼品包装税 + 商品促销折扣 + 货件促销折扣
```

共 **8项** 费用参与计算。

### ✅ 对比结论：完全一致

新公式和后端取的都是配送表同样 8 个费用项 × 发货日期汇率，无差异。

---

## 二、退款金额

### 数据源
结算报告（SalesData），交易分类（transactionCategory）= refund

### 筛选条件
通过订单号（orderId）关联配送数据，配送日期（shipDate）在目标季度范围内的退款记录纳入计算。

### 汇率
使用该订单关联的配送日期汇率（与筛选条件同源，都来自配送数据）。

### 新公式

```
退款金额 = Σ（每笔退款的退款小计 × 配送日期汇率）

退款小计 = 产品销售额 + 产品税 + 运费收入 + 运费税 + 礼品包装收入 + 礼品包装税 + 监管费 + 监管费税 + 促销折扣
```

共 **9项**，逐项明细：

| 序号 | 费用名称 | 系统字段 |
|------|---------|---------|
| 1 | 产品销售额 | productSales |
| 2 | 产品税 | productSalesTax |
| 3 | 运费收入 | shippingCredits |
| 4 | 运费税 | shippingCreditsTax |
| 5 | 礼品包装收入 | giftWrapCredits |
| 6 | 礼品包装税 | giftWrapCreditsTax |
| 7 | 监管费 | regulatoryFee |
| 8 | 监管费税 | regulatoryFeeTax |
| 9 | 促销折扣 | promotionalRebates |

### 后端现有逻辑

```
退款小计 = 产品销售额 + 产品税 + 运费收入 + 运费税 + 礼品包装收入 + 礼品包装税 + 促销折扣 + 促销折扣税
```

共 **8项**（`calculateRefundAmount` 方法），逐项明细：

| 序号 | 费用名称 | 系统字段 |
|------|---------|---------|
| 1 | 产品销售额 | productSales |
| 2 | 产品税 | productSalesTax |
| 3 | 运费收入 | shippingCredits |
| 4 | 运费税 | shippingCreditsTax |
| 5 | 礼品包装收入 | giftWrapCredits |
| 6 | 礼品包装税 | giftWrapCreditsTax |
| 7 | 促销折扣 | promotionalRebates |
| 8 | 促销折扣税 | promotionalRebatesTax |

筛选口径（前端实际使用 Amazon 口径 `refundBySettlementAmazonCny`）：
- 交易分类=refund + **交易日期**在季度内（`refundListAmazon`），不要求订单号在配送数据中
- 汇率：优先用配送汇率，回退交易日期汇率

> 注：后端 Amazon 口径按交易日期筛选，与新公式按配送日期筛选存在口径差异。此外后端还计算了另外两个维度（按发货归属/按结算时间），前端均未使用，应清理。

### ⚠️ 差异汇总

| 差异点 | 新公式 | 后端现有 |
|--------|--------|---------|
| 筛选条件 | 通过订单号关联配送数据，配送日期在季度内 | 交易日期在季度内（不关联配送数据） |
| 监管费（regulatoryFee） | ✅ 包含 | ❌ 不含 |
| 监管费税（regulatoryFeeTax） | ✅ 包含 | ❌ 不含 |
| 促销折扣税（promotionalRebatesTax） | ❌ 不含 | ✅ 包含 |
| 汇率 | 配送日期汇率 | 优先配送汇率，回退交易日期汇率 |

### 需调整

1. **退款筛选口径**：从按交易日期改为通过订单号关联配送数据、按配送日期在季度内筛选。
2. **退款费用项**：加入 regulatoryFee + regulatoryFeeTax，移除 promotionalRebatesTax，调整后共 9 项。
3. **冗余维度清理**：后端的 refundByShipment、refundBySettlement、refundBySettlementAmazon 三个维度统一为单一配送日期口径。

## 三、平台扣费合计

### 数据源
结算报告（SalesData）

### 费用分类

平台扣费分为三类：

| 费用类别 | 包含费用项 | 系统字段 |
|---------|-----------|---------|
| 佣金服务费 | 销售费用 + FBA费用 + 其他交易费 | sellingFees + fbaFees + otherTransactionFees |
| 其他费 | 其他 | other |
| 税 | 平台代扣税 | marketplaceWithheldTax |

### 统计方式（每类费用都按以下两种方式叠加）

| 统计方式 | 适用数据 | 筛选条件 | 汇率 |
|---------|---------|---------|------|
| 方式一 | income + refund 类型 | 通过订单号关联配送数据，配送日期在季度内 | 配送日期汇率 |
| 方式二 | 其他类型（排除 Transfer） | 交易日期在季度内 | 交易日期汇率 |

> 方式一详细说明：先筛选出发货日期在季度内的配送订单号集合，再从结算报告中取 income/refund 类型且订单号在该集合中的记录。即"配送日期在季度内"是对配送表的筛选，通过订单号关联到结算报告数据。

```
佣金服务费合计 = 方式一的佣金服务费 + 方式二的佣金服务费
其他费合计 = 方式一的其他费 + 方式二的其他费
税合计 = 方式一的税 + 方式二的税
```

### 后端现有逻辑

**方式一（income/refund 类型）**：

筛选方式：
- income：订单号在本季度配送订单集合中（`shippingOrderIds`）✅
- refund 费用：订单号在配送数据中 + 配送日期在季度内（`refundList` 维度二）✅
- 汇率：配送汇率 ✅

费用归类差异：
- 佣金服务费 = sellingFees + fbaFees + otherTransactionFees + **other**（4项，把 other 混在佣金里）
- 税 = marketplaceWithheldTax ✅
- 其他费 = ❌ 未单独拆出

**方式二（其他类型，排除 Transfer）**：
- 取 `total` 字段（合计列），不是单独的费用项
- 按 transactionType 拆分为 ServiceFee / 其他
- 汇率：交易日期汇率 ✅
- ❌ 未统计 marketplaceWithheldTax

### ⚠️ 差异汇总

| 差异点 | 新公式 | 后端现有 |
|--------|--------|---------|
| 方式一：佣金服务费组成 | 3项（sellingFees+fbaFees+otherTransactionFees） | 4项（多了 other） |
| 方式一：其他费 | 单独拆出 other | other 混在佣金服务费里 |
| 方式二：费用取值 | 取具体费用项（佣金3项+other+平台代扣税） | 取 total 字段（包含非费用项，金额可能偏大） |
| 方式二：平台代扣税 | ✅ 包含 | ❌ 不含（仅统计 income+refund 类型） |
| 方式二：费用归类 | 按费用类别（佣金/其他费/税）分别归入 | 按 transactionType（ServiceFee/其他）拆分 |

### 需调整

1. **方式一佣金服务费**：从 4 项改为 3 项，把 other 拆出去单独作为"其他费"。
2. **方式二费用取值**：从取 total 改为取具体费用项（sellingFees + fbaFees + otherTransactionFees + other + marketplaceWithheldTax），分别归入对应类别。
3. **方式二平台代扣税**：从仅 income+refund 扩大到包含其他类型（排除 Transfer）。

## 四、差异总览

| 指标 | 新公式 | 后端现有 | 状态 |
|------|--------|---------|------|
| 收入总额 | 配送表 8项费用 × 发货日期汇率 | 同 | ✅ 一致 |
| 退款金额 | 9项(含监管费+监管费税,不含促销折扣税)，按配送日期筛选 × 配送日期汇率 | 8项(含促销折扣税,不含监管费+监管费税)，按交易日期筛选 × 配送汇率 | ⚠️ 差异 |
| 退款维度 | 单一口径（配送日期在季度内） | 三个维度（前端用Amazon口径=交易日期，其余冗余） | ⚠️ 需清理 |
| 佣金服务费(方式一) | 3项(sellingFees+fbaFees+otherTransactionFees) | 4项(多了other) | ⚠️ 差异 |
| 其他费(方式一) | 单独拆出 other | 混在佣金里 | ⚠️ 差异 |
| 费用取值(方式二) | 取具体费用项 | 取 total 字段 | ⚠️ 差异 |
| 平台代扣税范围 | 所有非Transfer类型 | 仅income+refund类型 | ⚠️ 差异 |

## 五、建议调整方向

### 5.1 退款：明确单一口径
- 报税汇总输出**单一退款口径**，不再模棱两可
- 口径：交易分类=refund + 通过订单号关联配送数据 + 配送日期在季度内 + 配送日期汇率
- 清理后端冗余的三个退款维度，统一为配送日期口径

### 5.2 退款：调整费用项
- 加入监管费 + 监管费税（新公式包含，后端缺失）
- 移除促销折扣税（新公式不含，后端多算了）
- 调整后共 9 项：产品销售额、产品税、运费收入、运费税、礼品包装收入、礼品包装税、监管费、监管费税、促销折扣

### 5.3 费用合计：调整归类和取值
- 方式一：佣金服务费从 4 项改为 3 项（sellingFees+fbaFees+otherTransactionFees），other 拆出单独作为"其他费"
- 方式二：从取 total 改为取具体费用项（佣金3项 + other + marketplaceWithheldTax），分别归入对应类别

### 5.4 平台代扣税：扩大范围
- 从仅 income/refund 扩大到所有非 Transfer 类型

### 5.5 汇率：统一规则
- 收入：发货日期汇率（不变）
- 退款：配送日期汇率（不变）
- 费用/税：income+refund 用配送日期汇率，其他类型用交易日期汇率
