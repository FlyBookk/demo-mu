# FBA单据生成业务逻辑说明

> 版本：v1.0
> 日期：2026-03-08
> 说明：本文档严格基于系统代码逻辑编写，供业务方了解单据生成规则及结果复核使用。

---

## 一、整体流程概览

系统支持生成四类单据，按以下顺序操作：

```
FBA货件数据
    ↓
① PO（采购订单）   — 按货件创建时间推算PO日期，合并同日货件
    ↓
② DN（送货单）     — 按锚点日期+21天周期分组货件
    ↓
③ 结算单           — 按自然月拆分，每月按4个站点各生成1份
    ↓
④ INV（发票）      — 基于结算单自动生成，日期为结算日后第3个工作日
```

---

## 二、工作日规则

所有日期计算均依赖以下工作日规则，**非工作日 = 周六、周日 + 法定节假日**。

### 2.1 法定节假日（硬编码，每年手动更新）

**2025年节假日：**

| 节日 | 日期 |
|------|------|
| 元旦 | 1月1日 |
| 春节 | 1月28日 ~ 2月4日（共8天） |
| 清明节 | 4月4日 ~ 4月6日 |
| 劳动节 | 5月1日 ~ 5月5日 |
| 端午节 | 5月31日 ~ 6月2日 |
| 国庆节+中秋节 | 10月1日 ~ 10月7日 |
| 圣诞节 | 12月25日 ~ 12月26日 |

**2026年节假日：**

| 节日 | 日期 |
|------|------|
| 元旦 | 1月1日 ~ 1月2日 |
| 春节 | 2月16日 ~ 2月22日（共7天） |
| 清明节 | 4月5日 ~ 4月6日 |
| 劳动节 | 5月1日 ~ 5月3日 |
| 端午节 | 6月19日 ~ 6月21日 |
| 中秋节 | 9月25日 |
| 国庆节 | 10月1日 ~ 10月7日 |
| 圣诞节 | 12月25日 ~ 12月26日 |

### 2.2 三个工作日计算函数

| 函数 | 说明 |
|------|------|
| `nearestWorkingDay(date)` | 当天是工作日则返回当天；否则向后找最近的工作日 |
| `nextWorkingDay(date)` | 从 date+1 开始向后找第一个工作日（不含当天） |
| `addWorkingDays(date, n)` | 从 date+1 开始向后数，找第 n 个工作日 |

> 注意：`addWorkingDays(date, 3)` 表示从 date 的下一天开始计数，找到第3个工作日，**不是 date 本身加3天**。

## 三、单据编号规则

所有单据编号格式统一为：**`YYYYMMDD` + 3位序号（补零）**

- 示例：`20250902001`、`20250902002`
- 序号范围：001 ~ 999
- 日期部分取该单据的关键日期（PO日期 / DN日期 / 结算日 / INV日期）

## 四、PO（采购订单）生成逻辑

### 4.1 输入数据

- 选定的FBA货件列表（每个货件包含：货件编号、货件名称、创建时间、MSKU明细、FBA仓库收货地址）

### 4.2 PO日期推算规则

根据货件创建时间（精确到秒）推算对应的PO日期：

| 货件创建日是星期几 | PO日期 |
|-----------------|--------|
| 周二 | 当天 |
| 周一 | 同周周二（+1天） |
| 周三 | 下周周二（+6天） |
| 周四 | 下周周二（+5天） |
| 周五 | 下周周二（+4天） |
| 周六 | 下周周二（+3天） |
| 周日 | 下周周二（+2天） |

推算出周二日期后，若该日期为非工作日（节假日），则用 `nearestWorkingDay()` 向后顺延到最近工作日。

### 4.3 货件排序与合并

1. 所有货件按**创建时间升序**排列
2. 推算出每个货件的PO日期
3. **相同PO日期的货件合并为一份PO**

### 4.4 PO明细内容

每份PO按货件分组，每个货件内每个MSKU独立一行：
- 每个货件的**第一行**填写FBA仓库收货地址（街道、城市、州/省、邮编、国家）
- 同一货件的后续MSKU行地址列留空

### 4.5 PO编号

- 格式：`PO日期（YYYYMMDD）` + 3位序号
- 序号从调用时传入的 `startSequence` 开始，每份PO递增1
- 示例：同一天生成第1份PO → `20250902001`

---

## 五、DN（送货单）生成逻辑

### 5.1 输入数据

- **锚点日期**（必须手动指定，不能早于所有货件对应的最晚PO日期）
- 选定的FBA货件列表

### 5.2 DN日期序列计算

1. 第一个DN日期 = `nearestWorkingDay(锚点日期)`（锚点日期本身是工作日则取当天）
2. 后续DN日期 = 前一个DN日期 + 21天，若为非工作日则 `nearestWorkingDay()` 顺延
3. 序列持续生成，直到覆盖所有货件（rangeEnd = max(最晚货件创建日期, 锚点日期) + 21天）

示例（锚点日期 = 2025-09-02，为周二工作日）：
```
DN1日期 = 2025-09-02
DN2日期 = 2025-09-23
DN3日期 = 2025-10-14（若为工作日）
...
```

### 5.3 货件分组规则

| DN编号 | 包含的货件 |
|--------|-----------|
| 第1个DN | 货件创建日期 ≤ 第1个DN日期 |
| 第2个DN | 第1个DN日期 < 货件创建日期 ≤ 第2个DN日期 |
| 第N个DN | 第N-1个DN日期 < 货件创建日期 ≤ 第N个DN日期 |
| 最后一个DN | 超出所有DN日期的货件也归入最后一个DN |

### 5.4 DN周期起始日

| DN编号 | 周期起始日 |
|--------|-----------|
| 第1个DN | 该组中最早的货件创建日期 |
| 第2个及后续DN | 上一个DN日期 + 1天 |

### 5.5 DN明细内容

- 每个MSKU独立一行，按顺序编号（lineNo）
- E列备注填写对应的货件编号（shipmentNo）

### 5.6 DN编号

- 格式：`DN日期（YYYYMMDD）` + 3位序号
- 序号从 `startSequence` 开始，每份DN递增1

## 六、结算单生成逻辑

### 6.1 输入数据
- 结算周期起止日期（periodStart ~ periodEnd）
- 结算数据明细（MSKU、数量、单价、货币、站点代码、交易日期）
- 站点值
- 当前店铺

结算数据来源：
1. 通过选择的站点和店铺及结算季度关联联配送数据，再关联 income 销售数据（按 orderId 匹配）
2. 独立查询站点和店铺及结算季度下 refund 退款数据（按结算日期在周期内过滤，不走货件关联）
3. 按月按SKU汇总 income 数量，减去 refund 数量，得到净数量
4. 净数量为负时顺延到下月抵扣（跨季度清零）
5. 单价从结算导入数据（t_settlement_import_data）中按MSKU匹配

### 6.2 按自然月拆分

将整个结算周期按**自然月**拆分：
- 示例：周期 2025-01-01 ~ 2025-03-31 → 拆分为1月、2月、3月三个子周期
- 每个子周期只取该月内的交易数据（按 transactionDate 过滤）
- 无 transactionDate 的数据归入当前处理月

### 6.3 MSKU汇总规则

同一站点内：
- 相同 MSKU 的数量相加
- 单价取第一条记录的值
- 最终按 **MSKU 字母升序**排列

### 6.4 金额计算

```
明细金额 = 数量 × 单价（精度4位小数，HALF_UP四舍五入）
结算单合计金额 = Σ 所有明细金额
```

### 6.5 结算日

```
结算日 = 该自然月的下个月5日
若下个月5日为非工作日 → nearestWorkingDay() 向后顺延
```

示例：
- 1月数据 → 结算日 = 2月5日（若为工作日则取2月5日，否则顺延）
- 9月数据 → 结算日 = 10月5日（2025年10月5日为周日，顺延至10月6日，但10月6日为国庆节假日，继续顺延至10月8日）

### 6.6 结算单编号

- 格式：`结算日（YYYYMMDD）` + 3位序号
- 同一结算日的4个站点序号从 `startSequence` 开始递增
- 示例（startSequence=1）：`20251005001`（US）、`20251005002`（CA）、`20251005003`（UK）、`20251005004`（EU）

### 6.7 空结算单过滤

总数量为0的结算单不入库（该站点当月无数据时自动跳过）。

### 6.9 表头按照当前店铺下的配置信息获取

## 七、INV（发票）生成逻辑

### 7.1 输入数据

- 已生成的结算单列表（直接基于结算单数据生成）

### 7.2 INV日期

```
INV日期 = addWorkingDays(结算日, 3)
        = 从结算日的下一天开始，向后数第3个工作日
```

示例：结算日 = 2025-10-08（周三）
- 第1个工作日：10月9日（周四）
- 第2个工作日：10月10日（周五）
- 第3个工作日：10月13日（周一，跳过周末）
- INV日期 = 2025-10-13

### 7.3 INV明细

完全复制对应结算单的明细：
- lineNo（行号）
- MSKU
- 数量（quantity）
- 单价（unitPrice）
- 金额（amount）

### 7.4 INV编号

- 格式：`INV日期（YYYYMMDD）` + 3位序号
- 序号规则与结算单相同，从 `startSequence` 开始递增

### 7.5 卖方/买方/银行信息

来自系统配置（DocumentPartyProperties），不在代码中硬编码，由运维人员在配置文件中维护。

## 八、各单据关联关系

```
FBA货件
  ├── 生成 PO（1个货件批次 → 1份或多份PO，按PO日期合并）
  └── 生成 DN（1个货件批次 → 1份或多份DN，按21天周期分组）

结算数据（来自配送数据+销售数据）
  └── 生成 结算单（每自然月 × 4站点 = 最多4份）
        └── 生成 INV（每份结算单 → 1份INV）
```

## 九、常见问题说明

**Q：为什么同一批货件会生成多份PO？**
A：货件创建时间不同，推算出的PO日期不同，不同PO日期的货件不能合并，因此生成多份PO。

**Q：DN锚点日期如何选择？**
A：锚点日期不能早于所有货件对应的最晚PO日期。通常选择第一批货件PO日期当天或之后的工作日。

**Q：结算单为什么按自然月拆分而不是按7天周期？**
A：系统代码按自然月（1月、2月...）拆分，每月生成一组结算单，结算日为下个月5日。

**Q：INV日期为什么不是结算日+1天？**
A：INV日期是结算日之后第3个工作日（从结算日的下一天开始计数），不是+1天。

**Q：结算单中同一MSKU有多条记录怎么处理？**
A：数量相加，单价取第一条记录的值，最终按MSKU字母升序排列。
