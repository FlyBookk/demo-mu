## 三、核心计算规则

### 3.1 交易类型分类

| 交易分类 | transaction_category | 对应来源(type) |
|---------|---------------------|---------------|
| 收入 | income | Shipment, Retrocharge |
| 退款 | refund | Refund |
| 其他 | fee, adjustment, other | ServiceFee, Adjustment, Liquidations 等 |

---

### 3.2 收入/退款类型的计算逻辑

**适用范围**：`transaction_category = 'income'` 或 `transaction_category = 'refund'`

#### 数据获取流程

**收入总额**（来自配送数据）：
```
┌─────────────────────────────────────────────────────────────────┐
│  1. 按查询时间范围筛选【配送数据】（发货时间在查询范围内）           │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│  2. 汇总每行配送数据的 total_amount（总计费用）                    │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│  3. 按配送数据的汇率换算为人民币                                   │
└─────────────────────────────────────────────────────────────────┘
```

**消费税、销售费用等**（仍来自销售数据，需订单号匹配）：
```
┌─────────────────────────────────────────────────────────────────┐
│  1. 获取配送数据的订单号列表                                       │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│  2. 根据订单号查询【销售数据】income 类型（扩展结算时间+2个月）     │
└─────────────────────────────────────────────────────────────────┘
```

#### 计算公式

**收入总额** = 配送数据总计费用（按发货日期、站点筛选，每行 totalAmount 求和；totalAmount 为空时按 8 项计算：商品价格+商品税+运费+运费税+礼品包装价格+礼品包装税费+商品促销折扣+货件促销折扣）

**退款总额** = 产品销售 + 产品税 + 运费支出 + 运费税 + 礼品包装费 + 礼品包装税 + 促销折扣（不含监管费，来自销售数据 refund 类型）

**平台代扣税** = marketplace_withheld_tax

**销售费用+FBA费用+交易费+其他** = selling_fees + fba_fees + other_transaction_fees + other（仅 income/refund 类型）

#### 字段映射

| 费用项 | 数据库字段 | 来源说明 |
|--------|-----------|---------|
| 产品销售 | product_sales | Principal |
| 产品税 | product_sales_tax | Tax, TaxAmount 等 |
| 运费收入 | shipping_credits | ShippingCharge, ShippingDiscount 等 |
| 运费税 | shipping_credits_tax | ShippingTax, ShippingDiscountTax |
| 礼品包装费 | gift_wrap_credits | GiftWrap, GiftwrapChargeback |
| 礼品包装税 | gift_wrap_credits_tax | GiftWrapTax |
| 监管费 | regulatory_fee | RegulatoryFee |
| 监管费税 | regulatory_fee_tax | TaxOnRegulatoryFee |
| 促销折扣 | promotional_rebates | PromotionDiscount |
| 促销折扣税 | promotional_rebates_tax | PromotionDiscountTax |
| 平台代扣税 | marketplace_withheld_tax | MarketplaceFacilitatorVAT/Tax 系列 |
| 销售费用 | selling_fees | Commission, RefundCommission |
| FBA费用 | fba_fees | FBAPerUnitFulfillmentFee 等 |
| 其他交易费 | other_transaction_fees | DigitalServicesFee 等 |
| 其他 | other | Revenue, FeeAmount 等 |

### 3.3 其他类型（非收入/退款）的计算逻辑

**适用范围**：`transaction_category` 不是 `income` 也不是 `refund`（即 fee、adjustment、other）

#### 数据获取流程（实际实现）

```
┌─────────────────────────────────────────────────────────────────┐
│  1. 按结算时间（transaction_date）在季度范围内查询【销售数据】     │
│     transaction_category NOT IN ('income', 'refund')             │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│  2. 按销售数据自带的汇率（exchange_rate）进行金额换算             │
└─────────────────────────────────────────────────────────────────┘
```

> 注：当前实现不区分有/无订单号，一律按结算时间归属季度、使用销售数据汇率。

#### 计算公式

**其他费** = 所有非收入/退款类型数据的 `total` 字段汇总（**按原始正负值相加，禁止使用绝对值**）

#### 费用分类拆分（ServiceFee / 其他）

非收入/退款类型数据按 `transaction_type` 拆分为两类展示：

| 分类 | 计算规则 |
|------|----------|
| **ServiceFee** | `transaction_type = 'ServiceFee'` 的销售数据 `total` 总计 |
| **其他** | `transaction_type NOT IN (Refund, Shipment, ServiceFee)` 的销售数据 `total` 总计 |

> 注：数据源为 `transaction_category NOT IN ('income', 'refund')`，故不含 Refund/Shipment，其他 = 非 ServiceFee 的剩余数据。

---

### 3.4 广告费计算

**数据来源**：广告数据表（t_advertising_data）

**归属季度**：账单周期（billing_start_date ~ billing_end_date）与查询季度有交集即计入

**金额**：使用 cost 字段，人民币取 amountCny（导入时已按 issue_date 汇率换算）

---

### 3.5 退款的双维度统计

| 维度 | 数据获取方式 | 汇率来源 | 用途 |
|------|-------------|---------|------|
| **按发货归属** | 配送数据订单号 → 销售数据 refund | 配送数据汇率（原订单配送日期） | 主要报税维度 |
| **按结算时间** | 配送数据订单号 → 销售数据 refund（transaction_date 在季度内） | 配送数据汇率（原订单配送日期） | 辅助参考维度 |

**退款订单筛选**：仅统计订单号在配送数据中的 refund 记录（按配送数据订单维度查询退货订单）。汇率优先使用配送数据中的汇率，若无则回退到退款交易日期汇率。

---

## 四、金额汇总规则（重要）

**所有金额必须按原始正负值自然相加，禁止使用绝对值（.abs() / Math.abs）进行汇总。**

- 收入、退款、费用等字段的正负号由数据本身决定
- 汇总时直接相加，不得对单项取绝对值后再累加
- 例外：增长率计算中的分母可使用 previous.abs()，仅用于百分比计算，不参与金额汇总

---

## 五、汇率使用规则

| 场景 | 汇率来源 | 说明 |
|------|---------|------|
| 收入计算 | 配送数据的发货日期汇率 | 从配送表获取 |
| 退款-按发货归属 | 配送数据汇率（原订单配送日期） | 从配送表获取，若无则回退销售数据汇率 |
| 退款-按结算时间 | 配送数据汇率（原订单配送日期） | 从配送表获取，若无则回退销售数据汇率 |
| **其他费用** | **销售数据汇率** | 一律使用销售数据自带的 exchange_rate |
| **广告费** | **发票开具日期(issue_date)汇率** | 导入时按开具时间从汇率表填充，amountCny 已换算 |

## 六、完整计算流程

```
┌─────────────────────────────────────────────────────────────────┐
│                        输入：站点 + 季度                          │
└──────────────────────────────┬──────────────────────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│  配送数据查询   │    │  销售数据查询   │    │  广告数据查询   │
│ (发货时间范围)  │    │ (扩展结算时间)  │    │ (账单周期交集)  │
└───────┬───────┘    └───────┬───────┘    └───────┬───────┘
        │                    │                    │
        └────────────────────┼────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                    数据关联（订单号匹配）                          │
└──────────────────────────────┬──────────────────────────────────┘
                               │
        ┌──────────────┬───────┼───────┬──────────────┐
        ▼              ▼       ▼       ▼              ▼
┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐
│  收入总额  │  │  退款总额  │  │ 平台代扣税│  │ 费用合计  │  │  其他费   │
│           │  │ (双维度)  │  │           │  │           │  │           │

```

## 八、数据模型（TaxReportSummary 实际字段）

```java
// 实际 TaxReportSummary 字段（以代码为准）

// === 基础信息 ===
String siteCode, siteName, yearQuarter, currencyCode;

// === 收入 ===
BigDecimal totalRevenue, totalRevenueCny;

// === 退款（双维度）===
BigDecimal refundByShipment, refundByShipmentCny;
Integer refundCountByShipment;
BigDecimal refundBySettlement, refundBySettlementCny;
Integer refundCountBySettlement;

// === 平台代扣税（即消费税）===
BigDecimal consumptionTax, consumptionTaxCny;

// === 销售费用+FBA费用+交易费+其他（仅 income/refund 类型）===
BigDecimal sellingFees, sellingFeesCny;
BigDecimal fbaFees, fbaFeesCny;
BigDecimal otherTransactionFees, otherTransactionFeesCny;
BigDecimal otherAmount, otherAmountCny;
BigDecimal totalServiceFee, totalServiceFeeCny;

// === 其他费（非 income/refund 类型，按 transaction_type 拆分）===
BigDecimal miscServiceFee, miscServiceFeeCny;   // transaction_type=ServiceFee 的 total 汇总
BigDecimal otherFees, otherFeesCny;             // 非 ServiceFee 的 total 汇总
Integer miscFeesCount;

// === 广告费 ===
BigDecimal advertisingCost, advertisingCostCny;

// === 总成本 ===
BigDecimal totalCost;  // = totalServiceFeeCny + miscServiceFeeCny + otherFeesCny + advertisingCostCny
```

> **FeeBreakdown 与 TaxReportSummary 口径差异**：FeeBreakdown 按 transaction_type 分组，每组的 amount = sellingFees+fbaFees+otherTransactionFees+other；TaxReportSummary 的 miscServiceFee/otherFees 使用 total 字段。两者数据源相同（fee/adjustment/other），但汇总口径不同。

## 九、已确认规则

| 序号 | 问题 | 确认结果 |
|------|------|----------|
| 1 | 销售费用+FBA费用+交易费+其他 统计范围 | **仅 transaction_category = income/refund 的数据** |
| 2 | "其他费"定义 | **transaction_category 不是 income/refund 的数据的 total 字段** |
| 3 | 采购金额 | **移除**，不在当前数据范畴内 |
| 4 | 平台代扣税统计范围 | 仅 income/refund 类型 |
| 5 | 报税汇总页净收入 | 移除，不再计算（Dashboard 仍展示净收入） |
| 6 | 金额汇总 | **禁止绝对值相加，按原始正负值自然汇总** |
