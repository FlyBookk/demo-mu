# 配送数据批量导入重复问题分析

## 分析日期
2026-03-30

## 问题描述
批量导入配送数据时，发现导入结果中存在大量"重复"记录被跳过，导致数据丢失。

## 数据源分析

|------|--------|-------------|-----------|

| **合计** | **120,962** | **3,258** | **0** |

**结论：CSV 文件中不存在真正的重复数据。所有 3,258 个"重复"均为同一订单包含多个不同商品（多商品订单）。**

典型示例（10月文件 Row 178 vs Row 179）：
- 相同字段：订单号 `111-2745749-0876266`、追踪编码 `TBA325566391051`、销售渠道 `amazon.com`
- 不同字段：货件商品编号、SKU（`TFUS2-D70-25-5` vs `TFUS2-D70-6-6`）、商品价格（32.39 vs 19.99）

## 根因分析

### 去重唯一键缺陷

当前 `buildUniqueKey` 方法使用 `orderId|siteCode|trackingNumber` 作为唯一键：

```java
private String buildUniqueKey(ShippingData data) {
    String orderId = data.getOrderId() != null ? data.getOrderId() : "";
    String siteCode = data.getSiteCode() != null ? data.getSiteCode() : "";
    String trackingNumber = data.getTrackingNumber() != null ? data.getTrackingNumber() : "";
    return orderId + "|" + siteCode + "|" + trackingNumber;
}
```

**问题：唯一键未包含 SKU 字段。** 同一订单购买多个不同 SKU 商品时，亚马逊会生成多行记录（订单号和追踪编码相同，但 SKU、价格等不同）。当前逻辑会将这些合法的不同商品行误判为重复，导致：

1. 同文件内：第一行插入成功，后续不同 SKU 行被跳过（数据丢失）
2. 重新导入时：已入库记录导致所有同订单行被误判为重复

### 数据库查询也缺少 SKU

`batchCheckDuplicates` 方法查询已有记录时，select 字段未包含 SKU：

```java
siteWrapper.select(ShippingData::getOrderId, ShippingData::getSiteCode, ShippingData::getTrackingNumber);
```

## 修复方案

### 1. `buildUniqueKey` 加入 SKU

```java
private String buildUniqueKey(ShippingData data) {
    String orderId = data.getOrderId() != null ? data.getOrderId() : "";
    String siteCode = data.getSiteCode() != null ? data.getSiteCode() : "";
    String trackingNumber = data.getTrackingNumber() != null ? data.getTrackingNumber() : "";
    String sku = data.getSku() != null ? data.getSku() : "";
    return orderId + "|" + siteCode + "|" + trackingNumber + "|" + sku;
}
```

### 2. `batchCheckDuplicates` 查询加入 SKU

```java
siteWrapper.eq(ShippingData::getSiteCode, siteCode)
        .in(ShippingData::getOrderId, orderIds)
        .select(ShippingData::getOrderId, ShippingData::getSiteCode,
                ShippingData::getTrackingNumber, ShippingData::getSku);
```

### 影响范围
- 修复后，多商品订单的每个 SKU 行都会被正确插入
- 阿斯特数据预计多导入 3,258 条合法记录

## 三组数据交叉对比总结

| 数据源 | 总行数 | 多商品订单（被误判为重复） | 真正重复 | 跨文件重复 |
|--------|--------|--------------------------|---------|-----------|
| 阿斯特 | 120,962 | 3,258 | 0 | 0 |
| 阿米蒂 | 11,145 | 384 | 0 | 0 |
| 温妮 | 52,786 | 1,299 | 0 | 0 |
| **合计** | **184,893** | **4,941** | **0** | **0** |

三组数据源（3个不同店铺）的分析结果完全吻合，确认：

1. CSV 源文件中不存在任何真正的重复数据
2. 所有被系统标记为"重复"的记录，均为同一订单包含多个不同 SKU 商品的合法行项
3. 根因是 `buildUniqueKey` 方法的唯一键 `orderId|siteCode|trackingNumber` 缺少 SKU 维度
4. 修复后预计可多导入 4,941 条被误跳过的合法记录（占总数据量的 2.67%）
