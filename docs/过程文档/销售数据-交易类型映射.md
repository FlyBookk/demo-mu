## 1. 数据源概述

### 1.1 ERP数据（结算中心-结算明细）

**表头结构**：
```
结算编号,订单号,店铺,国家,报告类型,配送方式,来源,MSKU,交易类型,结算时间,币种,金额,数量,结算状态,转账状态,Settlement ID,SKU,品名,FNSKU
```

**关键字段**：
- `来源`：对应亚马逊原始数据的 `type` 字段（Shipment/Refund/Adjustment等）
- `交易类型`：费用明细类型（Principal/Commission/FBAPerUnitFulfillmentFee等）

## 5. 交易分类(transaction_category)规则

| 分类代码 | 分类名称 | 判断规则 |
|---------|---------|---------|
| **income** | 收入类 | 来源为 Shipment、Retrocharge |
| **refund** | 退款类 | 来源为 Refund |
| **fee** | 费用类 | 来源为 ServiceFee、RemovalShipment、CouponPayment、SellerDealPayment、ProductAdsPayment |
| **adjustment** | 调整类 | 来源为 Adjustment、RemovalShipmentAdjustment、Chargeback |
| **other** | 其他类 | 来源为 Liquidations、Transfer 或无法归类 |

## 6. 映射优先级与默认值

### 6.1 ERP交易类型映射优先级

1. **精确匹配**：ERP交易类型与映射表完全匹配
2. **前缀匹配**：如 `MarketplaceFacilitatorVAT-*` 系列
3. **默认归类**：未识别的交易类型默认归入 `other` 字段

### 6.2 原始数据type映射优先级

1. **英语type精确匹配**
2. **德语type转换为英语后匹配**
3. **默认归类**：未识别的type默认设置 `transaction_category = 'other'`

---

## 7. 注意事项

1. **大小写敏感**：ERP交易类型区分大小写（如 `FeeAmount` vs `feeAmount`）
2. **德语字段**：德国站需要德语→英语的type映射
3. **数据清洗**：部分异常数据（如店铺名出现在来源列）需要过滤
4. **金额符号**：
   - 正数：收入/补偿
   - 负数：费用/扣款
5. **去重逻辑**：使用 `settlement_id + order_id + transaction_type + sku` 作为唯一键
