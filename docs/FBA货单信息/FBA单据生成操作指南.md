# FBA单据生成操作指南

## 一、概述

本系统用于生成FBA转口贸易所需的四类单据，按以下固定流程依次生成：

```
FBA货件导入 → PO采购订单 → DN送货单 → 结算数据导入 → 结算单 → INV发票
```

每类单据的角色：

| 单据 | 发起方 | 接收方 | 用途 |
|------|--------|--------|------|
| PO采购订单 | 慕声（买方） | 香港Andeo（卖方） | 采购指令，告知供应商需要发哪些货 |
| DN送货单 | 香港Andeo（卖方） | 慕声（买方） | 到货确认，证明货物已送达 |
| 结算单 | 慕声（买方） | 香港Andeo（卖方） | 按周期结算实际销售，确认应付金额 |
| INV发票 | 香港Andeo（卖方） | 慕声（买方） | 付款依据，供应商开具的商业发票 |

---

## 二、前置准备：导入FBA货件数据

在生成任何单据之前，必须先将亚马逊FBA货件明细数据导入系统。

### 操作路径

侧边栏 → FBA货件明细 → 数据导入

### 操作步骤

1. 从亚马逊后台下载FBA货件明细报告（Excel或CSV格式）
2. 进入「FBA货件明细 → 数据导入」页面
3. 拖拽或点击上传文件（支持批量上传多个文件）
4. 点击「开始导入」，系统自动解析货件编号、MSKU、数量、仓库地址等信息
5. 导入完成后，前往「数据列表」确认货件数据正确

### 注意事项

- 支持 .xlsx、.xls、.csv 格式，单文件最大50MB
- 系统自动去重，已导入的货件会被跳过
- 导入后可在「FBA货件明细 → 数据列表」中查看所有货件

## 三、第一步：生成PO采购订单

### 操作路径

侧边栏 → FBA单据管理 → 单据生成 → 第一步

### 什么是PO？

PO是慕声向香港Andeo发出的采购指令。每当亚马逊后台创建了新的FBA货件（即准备发货到FBA仓库），慕声就需要生成一份PO，告诉供应商"这批货我要了"。

### 操作步骤

1. 在「选择FBA货件」下拉框中，搜索并勾选需要纳入本次PO的货件
   - 下拉框显示格式：`货件编号 (SKU数量) 创建日期`
   - 支持搜索货件编号
   - 可多选，一份PO可包含1~7个货件
2. 点击「生成PO并下载Excel」
3. 系统自动生成PO并下载Excel文件到本地

### 如何选择货件？

将同一批次需要采购的货件选在一起。通常按以下逻辑分批：
- 同一周内在亚马逊后台创建的货件归为一批
- 一份PO通常包含1~3个货件，最多7个
- 不同国家站点（US/CA/UK/EU）的货件可以合并到同一份PO

### PO日期是怎么确定的？

PO日期由系统根据所选货件的创建时间自动推算，不需要手动输入。规则是：
- 取所选货件中最早的创建时间所在周的下一个工作日（优先周二）
- 这保证了同一批货件无论何时导出，PO日期始终一致

### PO编号规则

格式：`YYYYMMDD001`，例如 `20250902001`
- 日期部分 = PO日期
- 序号部分 = 当日第几份PO（通常为001）

## 四、第二步：生成DN送货单

### 操作路径

侧边栏 → FBA单据管理 → 单据生成 → 第二步

### 什么是DN？

DN是香港Andeo向慕声出具的送货确认单。与PO不同，DN不是每次发货都生成，而是每隔约3周（21天）批量生成一份，将这段时间内所有已采购的货件合并确认。

### 操作步骤

1. 设置「锚点日期」
2. 确认「关联货件」（已从PO步骤自动同步，也可手动调整）
3. 点击「生成DN并下载Excel」

### 锚点日期是什么？怎么选？

锚点日期是DN周期计算的起始参考点。系统从锚点日期开始，每隔21天生成一个DN日期节点，然后将货件按创建时间分配到对应的DN周期中。

选择建议：
- 使用第一批货件的发货日期作为锚点（例如 `2025-05-22`）
- 一旦确定锚点日期，后续所有DN都应使用同一个锚点，以保证日期序列的一致性
- 锚点日期确定后不要随意更改，否则会导致DN日期发生变化

### DN日期计算逻辑

```
DN日期序列 = 锚点 + 0×21天, 锚点 + 1×21天, 锚点 + 2×21天, ...
```

例如锚点为 2025-05-22：
- 第1份DN：2025-05-22
- 第2份DN：2025-06-12（5/22 + 21天 = 6/12）
- 第3份DN：2025-07-03（6/12 + 21天 = 7/3）
- ...

如果计算出的日期恰好是周末或节假日，系统会自动顺延到最近的工作日。

### DN编号规则

格式：`YYYYMMDD001`，日期部分 = DN日期

## 五、中间步骤：导入结算数据

### 操作路径

侧边栏 → FBA单据管理 → 结算数据导入

### 为什么需要单独导入结算数据？

结算单的数据来源与PO/DN不同。PO和DN基于FBA货件数据（发了什么货），而结算单基于实际销售数据（卖了多少、单价多少）。结算单的单价来自内部"税务汇总采购成本"推算，不是亚马逊的销售价格。

### 操作步骤

1. 选择「结算周期」（起止日期）
2. 上传结算数据Excel文件
3. 点击「开始导入」

### 数据校验

导入后可使用「数据一致性校验」功能：
1. 选择要校验的周期范围
2. 点击「执行校验」
3. 系统会检查结算单与INV的数据是否一致，发现问题会列出具体的不一致项

## 六、第三步：生成结算单

### 操作路径

侧边栏 → FBA单据管理 → 单据生成 → 第三步

### 什么是结算单？

结算单是慕声与香港Andeo之间的销售结算凭证。按照协议，每7天为一个结算周期，每个周期按4个站点（美国/加拿大/英国/欧盟）各生成一份结算单，共4份。

### 操作步骤

1. 选择「结算周期」的起止日期
2. 点击「生成结算单并下载Excel」
3. 系统自动生成4份结算单（按站点拆分）并逐一下载

### 结算周期怎么选？

结算周期遵循固定的7天规则：每周二开始，到下周一结束。

选择时需要注意：
- 起始日期应为某个周二
- 结束日期应为对应的下周一
- 例如：`2025-08-26（周二）~ 2025-09-01（周一）`

如果选择的范围跨越多个7天周期，系统会自动拆分为多个子周期分别生成。

### 结算日是哪天？

结算日 = 结算周期结束日之后的下一个工作日。

通常情况：
- 周期结束日是周一 → 结算日是周二
- 如果周二是节假日 → 顺延到周三或更后面的工作日

### 4份结算单的区别

| 序号后缀 | 站点 | 货币 |
|----------|------|------|
| 001 | 美国站 | USD |
| 002 | 加拿大站 | CAD |
| 003 | 英国站 | GBP |
| 004 | 欧盟站 | EUR |

每份结算单只包含对应站点的MSKU销售数据。

### 结算单编号规则

格式：`YYYYMMDD001` ~ `YYYYMMDD004`
- 日期部分 = 结算日
- 序号部分 = 站点序号（001=US, 002=CA, 003=UK, 004=EU）

## 七、第四步：生成INV发票

### 操作路径

侧边栏 → FBA单据管理 → 单据生成 → 第四步

### 什么是INV？

INV是香港Andeo向慕声开具的商业发票，与结算单是同一份数据的不同格式。每份结算单对应一份INV，所以也是4份。

### 操作步骤

1. 确认「选择结算单」（已从上一步自动选择）
2. 点击「生成INV并下载Excel」
3. 系统自动生成4份INV并打包为ZIP下载

### INV日期怎么确定？

INV日期 = 结算日 + 1个工作日

通常情况：
- 结算日是周二 → INV日期是周三
- 如果周三是节假日 → 顺延到下一个工作日

特殊情况示例：
- 结算日 2026-01-02（周五）→ INV日期 2026-01-05（周一），跳过了周末

### INV编号规则

格式：`YYYYMMDD001` ~ `YYYYMMDD004`
- 日期部分 = INV日期
- 序号部分 = 站点序号（与结算单一致）

## 八、日期选择逻辑总结

| 单据类型 | 需要手动选择的日期 | 系统自动计算的日期 | 计算规则 |
|---------|-------------------|-------------------|---------|
| PO | 无（选货件即可） | PO日期 | 基于货件创建时间推算 |
| DN | 锚点日期 | DN日期 | 锚点 + N×21天，非工作日顺延 |
| 结算单 | 结算周期（起止日期） | 结算日 | 周期结束日的下一个工作日 |
| INV | 无（基于结算单） | INV日期 | 结算日 + 1个工作日 |

### 关键原则

1. 同一批数据，无论何时导出，所有日期和金额必须完全一致
2. 所有日期基于输入数据确定性推算，不依赖当前系统时间
3. 工作日排除周末和法定节假日（元旦、春节、清明、劳动节、端午、中秋、国庆、圣诞）

## 九、单据查看与导出

### 单据列表

操作路径：侧边栏 → FBA单据管理 → 单据列表

功能：
- 按类型筛选（PO/DN/结算单/INV）
- 按编号搜索
- 按日期范围筛选
- 查看详情
- 单独导出Excel

### 批量导出

在单据生成流程中，每一步完成后都会自动下载对应的Excel文件。如需重新下载：
- 在生成页面点击「重新下载」按钮
- 或在单据列表中找到对应单据点击「导出」

## 十、常见问题

### Q1: 锚点日期选错了怎么办？

锚点日期决定了所有DN的日期序列。如果选错了，生成的DN日期会与预期不符。建议：
- 确定一个固定的锚点日期后记录下来，后续所有DN生成都使用同一个锚点
- 如果已经生成了错误的DN，需要在数据库中删除后重新生成

### Q2: 结算周期选错了会怎样？

系统会按你选择的范围自动划分7天子周期。如果起止日期不是标准的周二~周一：
- 系统仍然会从你选的起始日期开始，每7天划分一个周期
- 最后一个周期如果不足7天，按实际天数处理
- 建议严格按周二~周一选择，以保持与历史数据一致

### Q3: 提示"单据已存在"怎么办？

系统有幂等性保护，同一编号的单据不会重复生成。如果看到此提示：
- 说明该单据之前已经生成过
- 前往「单据列表」查找已有单据并导出即可

### Q4: 结算单没有数据怎么办？

生成结算单前必须先导入对应周期的结算数据。检查：
- 是否已在「结算数据导入」页面导入了该周期的数据
- 导入时选择的周期范围是否与生成时一致

### Q5: 各单据的文件命名规则是什么？

| 单据类型 | 文件名格式 |
|---------|-----------|
| PO | `{编号}-东莞市慕声商贸有限公司-Hong Kong Andeo Group Limited-PO.xlsx` |
| DN | `{编号}-Hong Kong Andeo Group Limited-東莞市慕聲商貿有限公司-送貨清單.xlsx` |
| 结算单 | `{编号}-东莞市慕声商贸有限公司-Hong Kong Andeo Group Limited-结算单.xlsx` |
| INV | `{编号}-Hong Kong Andeo Group Limited-Dongguan Musheng Trade Co., Ltd.-invoice.xlsx` |
