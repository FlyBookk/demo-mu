## 二、新版计算公式

### 2.1 收入总额 (保持现有逻辑)

**数据源**: 配送数据 (ShippingData)

```
收入(每条配送记录) = productPrice + productTax
                   + shippingPrice + shippingTax
                   + giftWrapPrice + giftWrapTax
                   + productPromotionDiscount + shipmentPromotionDiscount

收入(CNY) = 收入(GBP) × ExchangeRate(配送日期, 节假日顺延)

收入总额(CNY) = Σ 季度内所有配送记录的 收入(CNY)
```

**状态**: ✅ 无需修改，误差0.37%在可接受范围内

---

### 2.2 退款金额 (需修正)

**数据源**: 销售数据 (SalesData, transactionCategory="refund")

#### 新版公式

```
退款金额(每条退款记录) = |productSales + productSalesTax
                       + shippingCredits + shippingCreditsTax
                       + giftWrapCredits + giftWrapCreditsTax
                       + promotionalRebates + promotionalRebatesTax|

汇率获取优先级:
  1. orderRateMap[orderId]    — 原订单配送日期的汇率
  2. refund.exchangeRate      — 退款交易日期的汇率
  3. 1.0 (兜底)

退款(CNY) = 退款金额(GBP) × ExchangeRate

退款总额(CNY) = Σ 季度内所有退款记录的 退款(CNY)
```

#### 核心修正点

| 修正项 | 修正前 | 修正后 | 影响 |
|-------|-------|-------|------|
| **统计维度** | refundByShipment(按发货归属) | 按**结算时间**(交易日期在季度内) | +¥31,696 |
| **匹配范围** | 仅Q3配送订单的退款 | Q3内所有Refund交易 | 覆盖Q2发货→Q3退款 |
| **计算公式** | calculateRefundAmount (8项) | 保持不变 | ✅ 公式正确 |
| **汇率策略** | 配送日期汇率优先 | 保持不变 | ✅ 策略正确 |

#### 修正后的筛选逻辑伪代码

```java
// 修正前: 按发货归属维度
refundList = salesData.stream()
    .filter(s -> "refund".equals(s.getTransactionCategory()))
    .filter(s -> allShippingOrderIds.contains(s.getOrderId()))  // ← 限制在配送订单内
    .collect();

// 只统计发货日期在季度内的退款
if (shipDate != null && shipDate in [startDate, endDate])  // ← 二次限制

// 修正后: 按结算时间维度 (用于报税)
refundList = salesData.stream()
    .filter(s -> "refund".equals(s.getTransactionCategory()))
    .filter(s -> s.getTransactionDate().toLocalDate() in [startDate, endDate])  // ← 按交易日期
    .collect();

// 不再要求原订单必须在本季度配送数据中
// 汇率: 优先用 orderRateMap(覆盖Q3+Q2配送), 否则用退款交易日期汇率
```

### 2.3 佣金/服务费 (需修正)

**数据源**: 销售数据 (SalesData, 所有交易类型)

#### 新版公式

```
佣金/服务费(每条记录) = sellingFees + fbaFees + otherTransactionFees

(注: 不含 marketplaceWithheldTax, 不含 other)

汇率: 有配送记录用配送日期汇率，否则用交易日期汇率

佣金/服务费合计(CNY) = |Σ 所有记录的 佣金服务费(CNY)|
```

#### 核心修正点

| 修正项 | 修正前 | 修正后 | 影响 |
|-------|-------|-------|------|
| **包含字段** | selling+fba+otherTx+**other** | selling+fba+otherTx (去掉other) | 去除杂项干扰 |
| **统计范围** | 仅income+refund类型 | **所有交易类型** | 补全FBA Return Fee/Amazon Fees等 |
| **展示方式** | 拆分为"佣金"和"ServiceFee" | 合并为一个"佣金服务费合计" | 与Amazon口径一致 |

### 2.4 平台代扣税 (保持独立)

```
平台代扣税 = Σ marketplaceWithheldTax × ExchangeRate

统计范围: 所有包含 marketplaceWithheldTax 的交易记录
独立于佣金/服务费单独展示
```

**状态**: ✅ 逻辑正确，保持现有计算不变

---

### 2.5 其他费/杂项 (调整展示口径)

#### 旧版展示
```
ServiceFee = 非income/refund类型的total汇总 (含Transfer等大额转账)
其他 = Adjustment等杂项
```

#### 新版展示
```
其他费用 = Σ (所有交易类型的 other 字段) × ExchangeRate
         + Σ (非income/refund类型中，不属于 selling/fba/otherTx 的金额)

具体包含:
  - Adjustment.other: 调整金额
  - FBA Inventory Fee.other: FBA库存费
  - Transfer.other: 转账金额
  - Service Fee.other: 平台服务费(other字段部分)
  - Liquidations.productSales/Tax: 清仓收入
```

## 三、汇率匹配调整方案

### 3.1 当前问题

1. **7月1-30日无汇率**: Q3汇率数据仅从7/31开始，导致7月前30天(43%配送记录)使用7/31汇率回退
2. **顺延方向**: 当前向后顺延(找下一个工作日)，符合Amazon逻辑

### 3.2 调整方案

```
优先级:
1. 精确匹配: 配送日期 == 汇率日期 → 直接使用
2. 向后顺延: 配送日期无汇率 → 向后查找最近的工作日汇率
3. 最大顺延天数: 30天 (超出则使用汇率表中最后一条)

代码逻辑:
  for i in range(0, 30):
      candidateDate = shipDate + i天
      if candidateDate in rateTable:
          return rateTable[candidateDate]
  return fallbackRate  // 或报错
```

### 3.3 数据补充需求

- **必须补充**: 2025年7月1日-7月30日的GBP→CNY汇率数据
- **建议补充**: Q2(4-6月)配送数据中订单的配送日期及对应汇率，用于匹配Q2发货→Q3退款的订单汇率

SELECT SUM(
  ABS(IFNULL(product_sales,0) + IFNULL(product_sales_tax,0)

## 六、新旧逻辑对比图

### 退款统计

```
旧逻辑 (refundByShipment):
  配送数据(Q3) → 提取订单号集合 → 筛选refund中匹配的 → 再筛发货日期在Q3的
  结果: 只有Q3发货+Q3退款的订单

新逻辑 (refundByTransaction):
  SalesData(refund) → 筛选交易日期在Q3的 → 直接计算
  汇率: 优先匹配配送日期(Q3+Q2配送数据), 否则用交易日期
  结果: Q3所有退款(含Q2发货→Q3退款)
```

### 佣金服务费

```
旧逻辑:
  SalesData(income/refund) → selling+fba+otherTx+other → "佣金"
  SalesData(其他类型) → total → "ServiceFee"
  marketplace_withheld_tax → "平台代扣税"

新逻辑:
  SalesData(所有类型) → selling+fba+otherTx → "佣金服务费" (Amazon口径)
  marketplace_withheld_tax → "平台代扣税" (单独)
  SalesData(所有类型) → other → "其他费用" (单独)
```
