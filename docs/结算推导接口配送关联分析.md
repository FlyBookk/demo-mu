# 结算推导接口（settlement-derivation/derive）配送数据关联分析

## 分析日期
2026-03-30

## 分析目标
确认配送数据修复（加入 SKU 去重维度）后，结算推导是否存在重复计算风险。

## 推导流程概览

```
derive 请求（站点+采购成本）
  → SalesDataAggregator.aggregateNetSales()
    → Income 路径：配送数据 → 订单号集合(Set) → 关联销售数据 → 按 SKU 聚合净销量
    → Refund 路径：按结算日期查退款/调整 → 按 SKU 聚合负向数量
    → 合并两条路径
  → buildSiteResult()：按 SKU 加权计算单价
  → 写入 settlement_import_data（每个 MSKU 一条记录）
```

## 关键逻辑逐环节分析

### 1. 配送数据查询（无重复风险 ✅）

```java
// queryShippingData: 按 shopId + shipDate + siteCode 查询
wrapper.eq(ShippingData::getShopId, shopId)
       .ge(ShippingData::getShipDate, periodStart)
       .le(ShippingData::getShipDate, periodEnd)
       .in(ShippingData::getSiteCode, siteCodes);
```

查询配送数据本身不涉及去重，返回所有行（含多商品订单的多行）。

### 2. 订单号集合构建（无重复风险 ✅）

```java
Set<String> orderIds = new HashSet<>();
Map<String, BigDecimal> orderRateMap = new HashMap<>();
for (ShippingData shipping : shippingList) {
    orderIds.add(shipping.getOrderId());
    orderRateMap.put(shipping.getOrderId(), shipping.getExchangeRate());
}
```

使用 `Set<String>` 收集订单号，天然去重。同一订单多行配送不会导致订单号重复。

汇率映射同 tax-summary，`HashMap.put()` 会覆盖，分批发货场景有微小偏差（影响可忽略）。

### 3. 销售数据查询（无重复风险 ✅）

```java
// querySalesData: 按 orderId IN (...) + siteCode 查询
wrapper.eq(SalesData::getShopId, shopId)
       .in(SalesData::getOrderId, batch)
       .in(SalesData::getSiteCode, siteCodes);
```

用订单号集合（已去重）查询销售数据。配送数据多行不影响此查询结果。

### 4. 净销售数量计算（无重复风险 ✅，核心环节）

```java
// calculateNetSales: 按 siteCode + SKU 维度聚合
for (SalesData sales : salesList) {
    String siteCode = sales.getSiteCode();
    String sku = sales.getSku();
    int quantity = sales.getQuantity();
    // income 正向累加，refund 负向累减
    netSalesMap.computeIfAbsent(siteCode, k -> new HashMap<>())
               .merge(sku, delta, Integer::sum);
}
```

这是推导的核心。聚合维度是 `siteCode + SKU`，数据来源是销售数据（t_sales_data），不是配送数据。

销售数据中同一订单的不同 SKU 行各自有独立的 quantity，按 SKU 维度 merge 累加是正确的。
配送数据仅用于提供订单号集合和汇率，不参与数量计算。

### 5. 单价计算与写入（无重复风险 ✅）

```java
// buildSiteResult: 按 MSKU 加权计算单价
// 每个 MSKU 一条记录写入 settlement_import_data
for (MskuDerivationItem item : sr.getItems()) {
    entity.setMsku(item.getMsku());
    entity.setQuantity(item.getQuantity());
    entity.setUnitPrice(item.getUnitPrice());
    settlementImportDataMapper.insert(entity);
}
```

写入粒度是站点+MSKU，每个 MSKU 只有一条记录，不存在重复。

## 综合结论

| 计算环节 | 是否存在重复计算 | 说明 |
|---------|----------------|------|
| 配送数据查询 | ✅ 无重复 | 查询结果含多行，但仅用于提取订单号 |
| 订单号集合（Set 去重） | ✅ 无重复 | HashSet 天然去重 |
| 销售数据查询 | ✅ 无重复 | 用去重后的订单号查询，不受配送行数影响 |
| 净销售数量（按 SKU 聚合） | ✅ 无重复 | 数据源是销售数据，按 SKU merge 累加 |
| 汇率映射 | ⚠️ 微小偏差 | 同 tax-summary，分批发货场景覆盖 |
| 单价计算与写入 | ✅ 无重复 | 每个 MSKU 一条记录 |

**总结：结算推导接口在配送数据修复后，不会产生重复计算问题。**

推导的数量计算完全基于销售数据（t_sales_data）按 SKU 维度聚合，配送数据仅作为"桥梁"提供订单号集合和汇率。配送数据多行（多商品订单）不会影响推导结果。
